# PSModManager

> [!WARNING]
> 本项目全程使用 Codex 和 Claude Code 开发；由于作者工作繁忙，维护和问题回复可能不够及时。
> 使用前请备份重要的 Mod 配置和存档，遇到问题可提交脱敏后的复现步骤与日志。

**面向 Probably Stolen 正式版原生 Mono 模组的 Windows 本地管理器。** 选择游戏，导入完整目录 / ZIP 或从 Steam 创意工坊获取模组，在三栏工作区选择启用与顺序，保存后运行。权限放在详情中，启用不弹权限提示；游戏批准和实际运行结果分别显示。不配置 AI 也能完成本地管理。

## 温室风格与三栏工作区

界面以已确认的[正式版原型](docs/design/formal-release-ui/prototype.html)为基线：可用模组、启用与顺序、详情三栏；支持跨栏拖动、多选、全选、框选和撤销重做，待保存变更集中在底部。详情包含概览、权限、依赖、配置、文件和运行记录。设置、日志笔记本、导航与窗口外框保留原有温室风格。

原型中的演示状态不是实际运行证据；应用读取所选安装的原生包、游戏状态与日志。

## 便携使用

前往 [Releases](https://github.com/1299489456/PSModManager/releases/latest)，在 **Assets** 中下载 `PSModManager-v<版本号>-windows-x64.zip`。`Source code (zip)` / `Source code (tar.gz)` 是源码，不是可直接运行的程序。需要自行构建时，按[开发指南](docs/development/README.md)操作。

### 运行要求

- Windows 10 / 11 x64。
- .NET Framework 4.8 或更高版本、Microsoft Edge WebView2 Runtime。
- 已安装 Probably Stolen 正式版 Mono，模组使用游戏自带加载器。

便携包携带 Python 和元数据解析 helper 的 .NET 运行时，**不需要安装 Python、Node.js 或 .NET SDK**。不附带游戏、Mod、存档、MelonLoader、Cpp2IL 或 Unity 生成依赖。

### 选择、保存、运行

1. **完整解压**便携 ZIP，运行 `PSModManager.exe`。保留同目录的 `PSModManager.WorkerHost.exe` 与 `_internal`，不要只复制一个 EXE。
2. **选择数据位置。** 首次启动可用默认的 `%LOCALAPPDATA%\PSModManager`，也可选择其他盘上的独立空目录。以后在“设置”→“数据位置”中迁移，完成后重启；游戏文件和存档不会搬动。
3. **选择游戏。** 管理器查找 Steam 安装，也可手动选择含 `Probably Stolen.exe` 的游戏根目录。在安装详情核对显示版本、内部版本、Steam Build 和 Mono 识别结果。
4. **准备 Mod。** 导入包含原生 manifest 的完整目录或 ZIP，核对预览后安装。工坊可使用本机已登录 Steam 会话订阅，等待下载完成后刷新；会话不可用时查看原因或打开官方页面。已经存在的原生包无需重复导入。
5. **启用与排序，再保存。** 开关、拖动和排序先加入底部“待保存”草稿；保存前创建恢复点。游戏运行中或无法确认进程状态时，只编辑草稿，不写入游戏。
6. **保存并启动，再对账。** 管理器核对清单与声明 DLL 指纹，保存用户启用批准和顺序，再等待启动结果；无需再进游戏模组菜单补做批准。普通流程不自动异常扫描，也不因未检查、旧报告或高风险报告自动拦截；主动隔离及未完成处置仍须处理。启动后查看 `Player.log` 确认实际加载。

“已安装”“目标启用”“游戏批准”“运行记录”彼此独立，保存成功不等于运行成功。当前游戏先加载 DLL 再应用保存顺序，排序不能保证初始化先后。导入不接受旧版裸 DLL 或安装脚本，不静默覆盖同 ID 本地包。更多操作见[快速开始](docs/user/quick-start.md)。

**需要排查异常时再检查。** 顶部独立“模组检查”页支持全部或选定模组、进度与证据；打开页面只读取记录，点击检查才扫描。可先预览有界摘要，再选择现有分析 Provider 辅助解读。检查和 AI 都不会自动处置模组，普通页面及启动不请求检查接口。

升级时先保留旧窗口的未保存选择并正常退出，再从新目录运行程序，在标题栏或“应用信息”核对实际版本 **0.3.5**。解压新包不会更新仍在运行的旧窗口，也不需要清空旧数据。

## 方案与恢复

方案保存原生模组 ID 和顺序，应用前预览缺失项与来源变化，再进入模组草稿。旧 MelonLoader 方案只预览迁移，不执行旧文件部署。恢复点可在方案页“⋯”查看；恢复也需关闭游戏，并保留新的恢复记录。

方案和恢复点不冻结 Steam 更新、不复制游戏批准，也不等于存档备份。模组文件分享仍需作者许可。

详细步骤见[方案、更新与在线 Mod](docs/user/sharing-updates-online.md)。

## Steam 创意工坊与可选智能分析

**创意工坊：** 浏览公开条目，通过本机已登录 Steam 会话订阅、取消订阅或请求更新选中项 / 全部待更新项。分别查看订阅、下载和安装状态，请求被接受不等于下载完成；会话不可用时可打开官方页面。管理器不索取 Steam 密码、不手写工坊 ACF。匿名下载不是账号订阅，未验证的能力保持不可用。

工坊卡片可直接操作，每页可选 12、24 或 48 项。元数据和封面缓存到本机，Steam 连接在后台探测；需要等待时显示具体状态，不阻塞其他页面操作。“管理器自动更新模组”默认关闭，只控制管理器请求，不能永久关闭 Steam 客户端自己的更新。

**详情阅读：** 缺少本地预览图时补用对应 Steam 条目封面，加载失败仍可阅读内容。工坊介绍可用 AI 翻译为中文，支持取消和切回原文；完整译文会缓存，切换原文 / 译文不重新请求。翻译只发送已取得的标题与介绍，不改变订阅或安装状态。

**AI 设置：** 在设置页管理多个 OpenAI 兼容或本地 Provider，分别选择日志分析和工坊翻译使用的服务。日志页仍用于阅读、分析和追问；不配置 AI 也能完成本地模组管理。发送前核对内容，启停建议须由你点击才会执行。外部模型可能产生费用，日志中也可能含个人信息，发送前请检查。

**不要上传密钥。** AI 密钥可仅本次使用，或保存在 Windows 凭据中；不要提交到 Git、Issue、截图或分享包。也不要上传个人数据库、游戏文件、存档或未脱敏日志。

## 数据、限制与问题反馈

程序和数据目录分开。删除便携程序目录不会自动删除数据或停用游戏里的 Mod；停用只修改启用列表，工坊文件由 Steam 管理。迁移、备份和重装见[数据与重装](docs/user/data-and-reinstall.md)。

查看[已知限制与验证边界](docs/development/known-limitations.md)。文件安装成功不等于游戏内兼容；本地接口测试不能代替真实游戏、WebView2、干净机器与 DPI 检查。

提交问题时请附上管理器版本、Windows 版本、具体操作、预期与实际结果，以及脱敏日志。不要提供真实账号密钥或整份游戏目录。
