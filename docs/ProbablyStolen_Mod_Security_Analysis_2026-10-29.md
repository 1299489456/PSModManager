# Probably Stolen 模组安全防御与 AI 分析方案

日期：2026-10-29。阶段：调查与设计，尚未实现或启用新的防护功能。

## 建议先做版本差异审查和启动前检查

管理器值得增加安全防御，但不应采用“大于 30 MB 判毒”或“AI 说安全就放行”的方式。推荐以**来源核对、全包静态检查、更新差异、杀毒引擎结果、启动前内容核对**为基础，让 AI 解释证据和帮助定位可疑代码。

最重要的保护对象不是“大文件”，而是**用户曾经信任的模组，更新后是否加入了用户没有预期的行为**。扫描结果必须绑定具体文件内容；游戏批准、管理器检查、用户风险例外分别记录。

## 游戏已有保护仍留下更新风险

当前安装 Build ID 为 26284217，与已有反编译证据的构建标签一致。以下是该 Build 的静态加载路径结论：

1. 禁用包可能被读取 DLL 字节进行格式初筛，但正常禁用路径不执行 `Assembly.LoadFrom`。
2. 游戏内启用时先用 Cecil 静态扫描，再走游戏批准流程；不是运行候选 DLL 来测试。
3. 已批准且指纹相同的包直接加载。指纹变化后，若扫描通过、检出能力没有超出历史批准集合，游戏可更新批准指纹并加载。
4. 游戏指纹覆盖 manifest 和声明 DLL，不覆盖全包资源、JSON 和所有其他文件。
5. 获准代码在游戏进程中执行，没有逐次拦截文件/联网调用的操作系统沙箱。停用不能撤回当前进程已经执行的代码或副作用。

因此，“游戏已批准”不应在管理器中显示为“安全”。同样拥有 files 和 network 能力的两个版本，实际行为可以完全不同。管理器需要比较内容和调用变化，而不只是比较权限列表。

原始定位见仓库既有证据文档及 `.preview/formal-release-audit/game-decompiled`：`ModLoader.cs:270–354,806–823,900–922,1014–1047`、`ModFingerprint.cs:15–31`、`ModScanner.cs:970–1000`。

## 推荐功能清单

P0 是首版应形成的完整保护闭环；P1 在稳定的证据格式上增强解释；P2 属于成本较高的专家能力。

| 优先级 | 功能 | 用户得到的结果 | 判断和处置原则 |
| --- | --- | --- | --- |
| P0 | 来源核对 | 显示 Workshop ID、上传者主页、上传/更新时间、本地来源、是否存在同 ID 本地覆盖 | 清单 Author 与昵称都可仿冒；原作者/授权关系必须有外部可核对证据，未知就显示未知 |
| P0 | 体积解释 | 按代码、嵌入资源、图片音频、依赖库、重复文件分类，列出最大的文件 | 不设置全类型统一的 30 MB 黑线；同包版本变化比跨类型排名更有价值 |
| P0 | 全包检查与内容基线 | 发现隐藏/未声明可执行物、异常路径、原生 DLL、脚本、嵌套归档和解析失败 | 依据文件内容而非扩展名；不能只扫描 manifest 中列出的 DLL |
| P0 | 更新差异审查 | 列出新增/删除/修改文件，代码与资源增量，新增依赖、域名、进程调用等 | Workshop ID、版本号和权限没变，也不能沿用旧内容的检查结果 |
| P0 | 基础 IL 风险检查 | 定位文件访问、联网、进程创建、动态加载、持久化等调用及所在方法 | 先看用途和组合证据；仅引用一个 API 不等于真正执行该行为 |
| P0 | 本机杀毒引擎接入 | 展示引擎、签名时间、检测名称、覆盖范围及扫描是否完成 | 可用时接入 Defender；不偷偷关闭保护、添加白名单或自动删除文件；引擎缺失不影响普通浏览与整理 |
| P0 | 受控启动检查 | 从管理器启动前检查启用包的最新内容和未完成更新 | 高可信恶意匹配或引擎严重告警默认停止该次启动；普通疑点提供详情与明确处置，避免一条 network 就封整个包 |
| P0 | 停用与可恢复处置 | 一键查看受影响方案/依赖，退出游戏后停用；隔离另行确认 | 游戏运行时不假装热卸载。隔离目录必须在游戏和工坊扫描范围之外；不直接删除 Steam 管理的文件 |
| P1 | AI 安全分析 | 解释可疑调用、功能与权限是否相称，以及新旧版的关键差异 | AI 引用文件、方法和证据编号；不能批准模组、取消引擎告警或自动操作文件 |
| P1 | 可选信誉查询 | 用文件 SHA-256 查询已有报告，显示报告年龄与各引擎结论 | 默认关闭外部请求；未收录不等于安全，单引擎结果需要复核；上传样本另行授权 |
| P1 | 来源对照与审查导出 | 用户指定原版与待比较包，获得结构/程序集/方法差异与脱敏报告 | 不凭相似度自动认定盗传；不自动在工坊发表评论或举报 |
| P2 | 专家动态分析 | 在专用隔离环境观察网络、文件和进程行为 | 不在日常游戏进程中试运行可疑 Mod；不共享宿主账号、存档、剪贴板和可写目录 |

### 静态分析应看行为组合

优先复核的组合包括：与模组用途无关的浏览器凭据/会话数据读取后外发，下载数据后交给进程或动态加载器执行，新增自启动/计划任务，以及修改系统安全设置。报告需要分清“可达调用链”“静态引用”和“仅出现字符串”。

正常游戏配置读取、联机通信、打开作者主页也可能使用类似 API。应将第一方业务代码、支持库和实际入口分开，避免把第三方库中未被使用的方法都算作模组行为。反射、加密或混淆导致分析不完整时，保留缺口，不补造调用链。

## 下载和更新必须按 Steam 的真实行为设计

Valve 文档说明，订阅会尽快下载并安装；`SuspendDownloads` 暂停的是全部工坊下载，并在恢复或游戏结束后解除。它不是逐模组、持久的版本锁。[Steamworks ISteamUGC](https://partner.steamgames.com/doc/api/ISteamUGC#SubscribeItem)

- **下载前**：只有公开元数据，可提醒来源、大小、描述及历史变化；没有文件就不能宣称完成代码扫描。
- **本地 ZIP/目录导入**：可先复制到管理器私有暂存区完成检查，再决定是否导入游戏。
- **Steam 订阅包**：Steam 直接写入自身内容目录；管理器不能承诺先拦截全部字节。下载完成且内容稳定后建立只读检查快照，新内容处于待检查状态。
- **更新完成**：原版本的结论保留作历史，但不能覆盖新文件。全包内容变化时重新检查，不依赖版本字符串或文件时间戳。
- **启动前**：再次核对实际启用内容和检查基线，并检查活动下载。复制/扫描期间有变化则标为“内容变化，需重新检查”。

现有管理器的安装锁只协调本进程操作，不能锁住 Steam 更新、快捷方式启动或游戏自己下载。文件监视也不能保证先于恶意执行。首版准确承诺是**拦住经管理器发起的不满足检查策略的启动**，不是全系统实时防火墙。

真正需要固定某个版本时，可后续设计“已审查的本地固定副本”，同时明确订阅关系、本地遮蔽、依赖、来源变化导致游戏重新批准等影响。不要通过修改 Steam ACF、给目录设只读或删除下载文件伪装版本锁。

## AI 应做证据解释而不是裁判

在现有多 Provider 设置中增加第三个用途：**模组安全分析**。它可独立选择便宜模型、本地模型或较强模型，不改变日志分析和翻译的绑定；不配置 AI 也能完成本地检查、手动处置和启动检查。

### 输入与输出

默认发送：用户选择的模组公开说明、文件组成、变化摘要、规则命中及必要的方法片段。发送前展示范围；不默认发送整包 DLL、完整反编译源码、存档、账号、API Key 或个人路径。证据中的内容按不可信输入处理，Mod 内的“忽略规则”“请运行命令”等文本不能改变分析任务。

AI 输出应包含：

1. 需要优先查看的具体变化及其原因。
2. 对应文件、程序集、方法、IL 偏移或证据编号。
3. 这种能力与模组声明用途之间的关系。
4. 尚无法确定的路径，以及会改变建议的缺失信息。
5. “保留停用”“查看差异”“进一步人工审查”等建议，由宿主规则和用户执行处置。

不输出“99% 无毒”。AI 回答失败、超时或证据不足，不改变本地扫描结果，也不自动放行。安全分析任务只获取只读证据工具，不继承日志助手或其他功能的写入工具。

### 降低费用与重复等待

先完成本地规则和差异提取，再按需发给模型；优先分析新版本变动的方法及相关上下文，而不是每次上传所有支持库。缓存绑定完整内容指纹、对比基线、扫描规则/解析器版本、Provider、模型和分析规则；原文/结论切换直接读取缓存。结果完整成功才入缓存，强制重分析由用户显式触发。

SHA-256 在这里用于“报告是否仍对应这份内容”和可选恶意样本信誉匹配，不只是展示一个看起来专业的字符串。签名、强名称和哈希分别表示不同事实，都不能单独代表安全。

## 保持温室界面和现有批准约定

- **模组三栏**：行内增加一个简短安全状态；详情新增“安全”页签，与现有权限、文件和运行记录互相定位。
- **工坊卡片**：未下载时只显示来源/元数据检查；已下载才显示对应本地版本的检查状态。不能在远端条目上贴上其他版本的“已检查”。
- **详情安全页**：先显示结论和下一步，再显示风险证据、体积分布、更新差异、引擎结果、AI 分析。高级技术细节可展开。
- **待保存篮子与启动区**：标出涉及的风险项，提供去详情、停用、复核等操作。沿用启用不弹权限提示的要求，不重新增加逐模组权限确认框。
- **设置**：本地自动检查、启动检查强度、杀毒引擎状态、可选外部信誉服务、AI 安全分析 Provider 和单次预算。

建议状态用“未检查 / 检查中 / 检查未完成 / 未发现高风险项 / 需要复核 / 高风险告警”，同时显示检查版本、时间和覆盖范围。扫描超限、引擎不可用和解析失败不能变成绿色结果。

首次升级不要把现有模组批量删除、停用或写入批准；先后台建立检查结果。高风险启动阻断属于管理器的安全策略，不表示已经撤销游戏批准。需要停用时通过现有原生保存路径，在游戏退出后建立恢复点并写入；风险例外只绑定当前内容，不自动适用于下一次更新。

## 杀毒服务和隔离的实际限制

Defender 支持指定目录的自定义扫描，`-DisableRemediation` 可用于不自动处置的检查；结果须读取命令输出，不能只看一个成功退出码。不可用、超时、签名过旧要分别显示。[Microsoft 官方命令文档](https://learn.microsoft.com/en-us/defender-endpoint/command-line-arguments-microsoft-defender-antivirus)

管理器不主动上传不代表 Defender 一定完全离线：其云保护受用户系统设置管理。应显示有关状态，不擅自改系统策略。[Defender 云保护](https://learn.microsoft.com/en-us/defender-endpoint/cloud-protection-microsoft-defender-antivirus)

VirusTotal 支持按哈希查询已有报告。公共上传的样本可能与合作方和客户分享，不能作为默认静默动作；集成时还须核对适用许可和额度，不能内置公共共享密钥。[VirusTotal API](https://docs.virustotal.com/reference/overview)、[样本共享说明](https://docs.virustotal.com/docs/how-it-works)

游戏内停用不是系统清毒。若引擎已报恶意且样本曾运行，建议先退出游戏并使用系统安全产品处理主机；管理器最多恢复自己能证明涉及的模组状态，不能承诺撤销外部文件、进程或账号泄漏。

Windows Sandbox 的网络和剪贴板默认配置不适合直接当作恶意样本实验室；专家分析需要明确关闭共享并限制映射，且存在游戏/Steam 兼容性成本，因此不列为首版自动功能。[Windows Sandbox 配置](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file)

## 实现基础和验收重点

已有能力可以复用，不需要另造一个管理器：

- `backend/native_mods/packages.py`：文件清单、路径与未声明 DLL 检查、有限 PE/CLI 结构识别。
- `tools/PSModManager.Metadata/Program.cs`：PEReader 元数据与资源读取；完整 IL 风险分析仍需扩展。
- `backend/scanning/worker_sandbox.py`、`worker_client.py`：无能力 AppContainer、资源上限和超时；隔离失败不降级为普通进程。解析应针对私有快照，不加载候选程序集、不反序列化不可信资源对象。
- `backend/games/probably_stolen/launch.py`、`backend/workshop/service.py`：管理器启动路径和下载状态核对。
- 原生保存/恢复点与现有 Provider、取消、预算、缓存基础设施。

首版验收应证明以下行为：

1. 当前七包能够解释大小及权限，不因大图、Harmony 或合理联机接口被一刀切标成病毒；也不把这七包预先标注为无害真值。
2. 同一个 Workshop ID、相同版本号和相同权限集合，只要代码内容变化，旧结论就失效。
3. 新增资源、未声明文件、嵌入可执行内容、异常路径和读取失败都有可追踪结果。
