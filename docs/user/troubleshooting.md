# 常见问题

| 情况 | 处理 |
|---|---|
| 缺 WebView2 / .NET Framework，或只剩一个 EXE | 按提示准备运行环境，重新完整解压便携 ZIP，保留 `_internal` 和 WorkerHost；不混用不同版本文件 |
| 解压新版后仍在保存时扫描或提示旧报告拦截 | 先在标题栏或“应用信息”核对实际版本。0.3.0 / 0.3.1 旧窗口仍采用旧流程；保留未保存的选择并正常退出后，从新版目录启动并确认 0.3.5。不要只点旧快捷方式，不需要删除数据库或检查记录 |
| 找不到游戏 | 选择含 `Probably Stolen.exe` 的正式版根目录，不是 `Mods` 子目录；多个安装时核对顶部安装牌子 |
| 发现旧 MelonLoader / IL2CPP 文件 | 正式版使用原生 Mono。先备份并核对旧文件归属，不安装 Cpp2IL，也不让管理器自动删除未知文件 |
| DLL 或 ZIP 不能导入 | 使用包含原生 manifest 和配套文件的完整目录 / ZIP。裸 DLL、危险路径、链接、加密包、大小写冲突和超限展开会被拒绝；按预览提示处理 |
| 同 ID 已存在本地包 | 不会自动覆盖。先核对本地与工坊来源、备份原包并处理目录冲突，再重新预览 |
| 开关已打开，游戏却没有变化 | 开关修改的是草稿。关闭游戏后点击“保存并启动”，等待原生批准保存和启动结果；普通流程不自动异常扫描，无需再进游戏菜单补做批准 |
| 为什么启用不弹权限框 | 权限集中在详情“权限”页；保存记录本次内容的用户启用批准，不代表已检测或安全审计 |
| 已批准但显示未运行 / 等待重启 | 批准不等于本次加载。检查最近 `Player.log` 和“本次启动对账”；菜单内批准的包可能下次启动才加载 |
| 运行状态未知 | 缺少可靠日志或进程证据时保持未知。正常启动后刷新；不要用旧日志或已安装状态代替运行证明 |
| 自动排序后仍有冲突 | 排序只处理已知依赖和保存顺序；当前游戏先加载 DLL 再应用顺序，不能解决所有初始化或补丁冲突 |
| 缺失依赖 / 循环依赖 | 先安装缺失的原生包，或调整冲突组合。自动排序不会伪造依赖、隐去循环或擅自下载 |
| 游戏运行中 / 状态无法确认 | 可以继续整理草稿；正常关闭游戏，确认停止后再保存配置、安装或恢复。管理器不强制结束未知进程 |
| 保存提示列表或文件已改变 | Steam、游戏或其他程序在读取后改了状态。重新读取并核对差异，不用旧草稿覆盖新文件 |
| 保存成功但游戏报错 | 去日志页检查 `Player.log`，区分缺依赖、未批准、加载失败和玩法冲突；保存成功不代表兼容 |
| 未检查或高风险报告会阻止使用吗 | 0.3.2 起不会因这些报告自动阻断普通保存和启动。0.3.3 从顶部“模组检查”进入独立页面，打开只读取记录，点击检查才扫描；已主动隔离、未完成处置和实际运行/写入保护仍有效 |
| 保存或启动失败后如何重试 | 按本次具体原因处理后重试；新请求会清理上一轮错误，并等待各阶段结果。只读后台 Steam 探测会让出前台保存，真实下载、未确认任务或游戏运行仍需先处理 |
| 检查未完成 / 隔离解析器不可用 | 查看覆盖缺口和具体错误，核对便携包的 WorkerHost、helper 与运行环境。超时、超限或隔离失败保持未完成，不伪装通过；这份报告本身不阻止普通操作 |
| 版本号没变，却提示内容已变化 | 检查绑定全包文件内容，Steam 更新或其他文件修改都会使旧报告失效。等待内容稳定后重新检查，再查看新增、删除和修改文件 |
| 模组有联网、P/Invoke 或很大的 DLL | 查看具体调用和资源组成；单项能力或大小不独立判恶意。高风险告警需核对证据，不能只看作者名称或游戏已批准 |
| Defender 不可用 / 没有检查 | 基础静态检查和引擎结果分开。需要时主动请求 Defender 检查；查看系统引擎状态，不关闭保护、不添加白名单。云保护由系统设置控制 |
| 工坊隔离后文件还在 | 工坊隔离只阻止管理器受控启动，不改 Steam 文件、ACF 或订阅；不能阻止从 Steam 或 EXE 直接启动 |
| 解除隔离后仍不能启动 | 恢复不会自动启用或恢复旧批准；核对实际文件、启用选择及未完成处置后再保存。重新检查是可选操作，不是恢复后的强制步骤 |
| 检查或处置记录损坏 | 保留应用数据和错误信息。普通报告损坏不等于已隔离；若处置状态无法确认，按具体错误恢复，不删除隔离记录绕过限制 |
| 模组检查的 AI 分析会发送什么 | 先查看独立检查页里的实际摘要预览，再主动发送到设置中“日志分析”绑定的 Provider；AI 只解读，不自动处置。取消或失败不会影响普通保存和启动 |
| Steam 会话不可用 / 订阅未知 | 启动并登录 Steam，核对所选正式版安装及账号权限后刷新；接口仍不可用时查看具体原因或打开官方页面。本机已安装不能单独证明当前账号已订阅 |
| Steam 已连接，目录却显示缓存或加载中 | 公开目录与账号会话是两条状态。搜索、筛选和翻页在后台读取，先显示对应缓存或加载状态；目录过期或读取失败不要求重新登录 Steam |
| 游戏已退出，仍不能执行工坊操作 | 看具体原因：后台连接、安装锁占用、会话失败或进程未知需要不同处理；不要反复退出已停止的游戏。先等待当前操作结束或按连接提示修正 |
| 升级前保留过 Demo 数据，工坊一直提示操作中 | 0.2.3 修复了旧安装历史记录误阻断正式版的问题。关闭旧管理器、完整解压新版并沿用原数据目录，再刷新工坊；不要删除旧恢复记录来绕过检查 |
| 工坊提示有待恢复记录 | 保留应用数据和旧游戏旁的 `.psmm-*` 目录，按具体恢复错误核对；当前安装未决记录或无法确认归属的记录仍需处理。重连 Steam 或反复退出游戏不能修复这类问题 |
| 订阅或更新请求成功，但包没有变化 | 请求确认不等于下载完成。检查 Steam 排队及下载状态，等待完成后刷新；核对是否有同 ID 本地副本遮蔽工坊包 |
| 没点更新，待更新数量却减少 | Steam 客户端可能已自行下载。刷新查看实际版本和状态；“管理器自动更新模组”默认关闭，只约束管理器请求，不能永久禁止 Steam 自己更新 |
| 批量更新只有部分成功 | 查看逐项结果；失败项按提示重试。已接受的任务由 Steam 继续处理，不要把重开管理器当作取消队列 |
| 工坊操作结果待确认，启动或迁移被阻止 | 超时或会话中断后不要重复提交。恢复 Steam 连接并刷新，核对实际订阅/下载状态；未确认项或活动下载解除后再启动或迁移 |
| 详情缺少封面 | 优先用包内图及已缓存封面；仍缺失时获取 Steam 图片。没有可用图片则显示占位，不影响操作；缓存不会证明模组已安装或已订阅 |
| 工坊 AI 翻译失败 / 只译了部分 | 在设置页检查“翻译”绑定的 Provider、模型与密钥；可取消并切回原文。失败或取消不会写成完整缓存，被截断的介绍不会冒充全文 |
| 日志分析与翻译使用了不同服务 | 两项分别绑定 Provider；在设置页核对对应选择，不必修改另一项。仅本次密钥重启后需重新提供 |
| Provider 无法删除 / 修改后仍在使用旧服务 | 先将分析和翻译改绑，才能删除正在使用的 Provider；进行中任务固定使用启动时的服务，改绑只影响之后的新任务 |
| 更换服务地址后提示缺密钥 | 为避免把旧服务密钥发给新地址，需要为新地址重新提供密钥；单纯编辑同一服务时留空会保留原密钥 |
| 切换原文 / 译文会不会重复调用 | 显示已有完整译文时不发起新请求；介绍或翻译配置变化后，可能需要重新翻译 |
| 译文缓存无法读取或已满 | 保留应用目录中的 `ai-translations.json` 并处理具体错误；16 MiB 上限不会自动删除旧译文，也不会把缓存错误当成未命中后再次收费请求 |
| 匿名用户不能订阅 / 下载 | 匿名下载不是账号订阅；当前未验证本游戏匿名下载能力。使用本机已登录 Steam 会话，不提供密码给管理器 |
| 工坊请求失败或显示缓存 | 网络失败不阻塞本地管理。可重试或打开官方页面；401/403 不会通过换通道绕过 |
| 配置只有文本输入，没有开关或范围 | 原生配置文件只保存字符串，缺少类型定义时不能可靠推断。编辑已知键，保存前关闭游戏，原有未知字段会保留 |
| 恢复后仍需批准 / 版本没回去 | 恢复点不复制历史批准，也不冻结 Steam 包文件。核对实际来源和版本后显式保存，为当前选择写入启用批准；不强制异常扫描 |
| 旧方案无法直接应用 | 旧 MelonLoader 方案只供迁移预览；补齐正式版原生包并核对真实 ID 后建立新方案 |
| 权限、空间不足或文件占用 | 使用当前用户可写目录，关闭占用文件的编辑器并释放空间。失败不会被当作保存成功，不自动提权 |
| 数据迁移或恢复失败 | 保留原应用数据与历史 `.psmm-*` 备份，查看具体错误；不要手工合并不完整目录或只覆盖数据库 |
| AI 不可用 / 查询超时 | 在设置页检查对应功能绑定的 Provider、模型与密钥；可继续本地管理。部分资料未取得时保持未知，已收到内容保留，按需继续分析 |
| AI 建议已失效 | 模组列表或文件已改变，刷新后重新分析，不让旧建议覆盖当前状态 |

反馈问题时提供管理器版本、Windows 版本、所选游戏版本、操作步骤、错误原文和脱敏日志。不要上传密码、密钥、完整存档或游戏目录。

便携包未作发布签名。Windows 出现来源提示时先核对发布者与下载完整性，不通过关闭系统防护掩盖文件异常。包内 `SHA256SUMS.txt` 对应展开后的文件，ZIP 外部同名清单对应下载包。
