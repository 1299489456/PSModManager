# Steam 创意工坊与原生方案

## 用本机 Steam 账号管理订阅

1. 启动 Steam 并登录拥有 Probably Stolen 的账号，在管理器选择已安装的正式版游戏。
2. 打开“创意工坊”，搜索或浏览条目，查看介绍、作者、更新时间与已知依赖。点击订阅后，管理器通过官方 Steam UGC 接口提交请求并核对结果，不需要你提供密码。
3. 等待 Steam 下载完成，再刷新本机状态。订阅确认只说明账号状态已改变；本机内容完整后，才能在“模组”页检查、启用并保存。

会话初始化失败、客户端未登录、游戏接口不可用等情况会显示具体原因；可先修正后刷新，也可打开官方页面处理。Steam 与管理器应使用同一 Windows 用户及权限上下文，不要只将其中一个以管理员身份运行。打开页面不是订阅成功，管理器不会在未取得账号证据时把“本机已安装”变成“当前账号已订阅”。网络失败时本地模组仍可管理，缓存会标明过期。

连接探测在后台完成，等待时仍可使用其他页面；只读探测让出前台保存，真实下载或未确认操作仍会阻止冲突动作。界面分别说明账号连接、公开目录读取和游戏进程状态，目录过期不要求重连账号。公开条目和封面缓存到本机，不能用这些缓存替代当前账号或进程状态。工坊卡片可直接操作，每页数量可选 12、24 或 48。

访问过的公开信息和图片可在断网、重开后复用；搜索、筛选和翻页先返回对应缓存或加载状态，再后台刷新，不等待整次网络请求才能切换。缓存容量有限，不保证所有历史条目永久保留；从未访问过的条目在离线时仍无法凭空加载。Steam 连接失败会保留上次观察并标为过期，不会把旧待更新状态改成当前已是最新。

直接操作需要所选安装位于 Steam 库中。手动原生安装仍可管理本地模组及启动游戏，但没有可用 Steam 安装信息时不启用工坊修改。

匿名下载与账号订阅是两件事。本游戏的匿名下载支持尚未验证，因此当前不可用，并显示原因；不安装 SteamCMD、不借用其他应用的授权。管理器不手写 Steam ACF 或工坊包，实际下载和安装由 Steam 完成。

取消订阅使用同一官方会话，需要先核对影响。它可能使 Steam 移除内容；操作前检查哪些方案或其他模组需要该包，不把取消订阅当作单纯停用。游戏运行或状态无法确认时不开始这些可能改变包的操作。

## 更新选中项或全部待更新项

在模组页点击“检查更新”，查看每个工坊条目的更新、下载和安装状态。“更新选中”处理所选可更新项，“全部更新”处理所有待更新项，超过 100 项时逐批完成后继续；工坊详情也可单独更新。本地目录 / ZIP 模组不属于 Steam 更新范围。

“下载请求已接受”只说明 Steam 接收了任务，可能仍在排队；之后刷新确认下载中、进度和安装结果。没有可靠逐项进度时不显示百分比，不把应用级 ACF 标记套用到每个包。批量操作逐项报告结果，不把部分失败写成全部成功。

超时或会话中断后，已提交项可能显示结果待确认；先恢复连接并刷新，不重复提交。未确认操作和活动下载会阻止从管理器启动游戏，执行中或未确认的操作也会阻止迁移应用数据。

更新不自动保存启用顺序，状态刷新不覆盖未保存草稿。关闭管理器不会取消 Steam 已接受的下载；Steam 自己的后台更新也不受管理器恢复点控制。游戏运行期间先正常关闭游戏，再发起管理器的更新请求。

### 自动更新开关只控制管理器

“管理器自动更新模组”默认关闭。开启后才允许管理器主动请求更新，仍须满足游戏退出、会话可用等条件；关闭后仍可手动更新。关闭会阻止自动批次尚未提交的项，已提交项继续核对结果。这个开关不能永久关闭 Steam 客户端的自动更新，也不能撤回已经接受的下载。即使管理器没有发出请求，Steam 自行下载后，待更新项也可能变为已是最新。

## 读介绍与使用 AI 翻译

模组详情优先使用包内预览图；缺失或加载失败时补用对应 Steam 条目封面，可点开大图。图片仍不可用时显示占位，文字和操作不受影响。工坊介绍保留原文，可使用设置页为“翻译”绑定的 Provider 翻译为中文，也可取消或随时切回原文；不必与日志分析使用相同服务。

点击翻译才发送已取得的标题和介绍；中文段落直接保留，不重复发送。原文被截断或超出翻译范围时，译文保留范围提示，全文可在官方页面阅读。读取、AI 调用失败或取消都不会改变订阅、安装或启用状态。外部服务可能收费，发送前核对自己的服务配置。

完整、未截断的译文会持久缓存；同一工坊条目、精确原文、Provider、服务地址、模型和翻译规则匹配时直接显示，切换原文 / 译文不会重新付费调用。不同 Provider 的缓存分别保存，切回原 Provider 可复用旧译文，只修改显示名称不会失效。失败、取消或截断结果不当作完整缓存。需要主动重新请求时使用“重新翻译”；介绍或服务配置变化后可能需要重新翻译。

译文缓存上限为 16 MiB，不会自动淘汰已有译文后悄悄重新付费请求。缓存损坏、无法读取或已满会明确提示；先保留已有数据并处理错误，不把读写失败当作缓存未命中。

## 保留一套启用顺序

在“方案”中创建或更新方案，保存本机可识别的原生模组 ID 和启用顺序。应用前先看缺失项、来源变化与依赖提示；应用结果进入模组草稿，核对后再“保存”到游戏。游戏运行时可以整理方案，但不能应用写入游戏。

方案不冻结 Steam 后续更新的包版本，也不携带游戏批准、存档或账号授权。需要保留某个版本时，先按作者许可自行备份原包。分享模组文件前确认作者允许再分发；分享一个列表不保证另一台电脑已经安装所需内容。

旧版 MelonLoader 方案只供迁移预览。只有明确映射到真实原生 ID 的项目可用于新草稿；旧 DLL 文件名或相似名称不能自动当作同一模组，无法识别的条目会保留为待处理项，不执行旧部署动作。

## 更新后重新核对运行结果

Steam 负责工坊更新，本地原生包通过目录 / ZIP 导入预览。管理器不会用旧版 DLL 扫描规则猜测原生身份，也不会静默覆盖已有同 ID 本地目录。出现重复来源时查看详情的实际生效路径；游戏通常先采用本地来源，订阅更新可能被本地副本遮蔽。

包文件变化后，旧批准、检查报告与最近一次运行证据可能不再适用于新包。刷新后核对来源和依赖，再显式保存或“保存并启动”，按当前清单与声明 DLL 指纹记录启用批准；普通流程不自动异常扫描。需要比较异常与内容差异时，从顶部独立“模组检查”页主动发起检查。保存成功不等于更新后的模组兼容，实际加载仍看 `Player.log`。
