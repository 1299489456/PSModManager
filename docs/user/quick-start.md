# 快速开始

## 选择游戏，准备原生模组

完整解压 Windows x64 便携 ZIP，运行 `PSModManager.exe`，保留同目录的 `_internal` 和 `PSModManager.WorkerHost.exe`。需要 Windows 10/11 x64、.NET Framework 4.8+ 和 WebView2 Runtime；不需要安装 Python、Node 或 .NET SDK。缺少运行环境时按提示处理，管理器不会静默安装。

**升级后先核对运行版本。** 先保留旧窗口中未保存的选择，再正常退出旧版，从新解压目录启动。在标题栏或“应用信息”确认显示 **0.3.5**；旧快捷方式或仍打开的旧窗口不会随解压自动升级。不要为切换版本清空应用数据。

第一次启动选择数据位置。默认是 `%LOCALAPPDATA%\PSModManager`，也可选择其他盘上的独立空目录；以后仍在“设置 → 数据位置”迁移。游戏和存档不会随应用数据搬动，详见[数据与重装](data-and-reinstall.md)。

在顶部安装牌子选择 Probably Stolen 正式版，或手动选择含 `Probably Stolen.exe` 的游戏根目录。安装详情分别展示游戏显示版本、内部版本、Steam Build 和 Mono 识别结果。正式版使用游戏自带加载器，**不安装 MelonLoader，也不需要 Cpp2IL**。发现旧版加载器遗留时先核对文件归属，管理器不自动删除。

获取模组有两条路径：

- **本地目录或 ZIP：** 点击导入，选择含原生 manifest 和配套文件的完整包，核对预览后安装到游戏 `Mods`。不接受只有一个 DLL 的旧版包，不执行 DLL 或安装脚本，不移动来源文件。目录冲突、危险路径、异常压缩包或展开超限会阻止安装；同 ID 已有本地包不会被静默覆盖。
- **Steam 创意工坊：** 启动 Steam 并登录拥有本游戏的账号，在管理器中浏览条目并订阅；会话不可用时查看原因，也可打开官方页面处理。等待 Steam 下载完成后刷新，本机内容出现才可启用；订阅成功不等于安装完成。匿名下载不是账号订阅；本游戏的匿名下载能力未经验证时保持不可用，见[工坊与方案](sharing-updates-online.md)。

## 三栏完成启用与顺序

“模组”页从左到右是 **可用模组 → 启用与顺序 → 模组详情**。点击行查看详情，开关或跨栏拖动修改启用草稿；中栏拖动调整保存顺序。Ctrl / Shift 可多选，也可全选或用鼠标框选；方案编辑使用同样的选择方式。支持撤销、重做，页面底部的“待保存”篮子集中显示变更。选中本身不改变启用状态。

1. 把要使用的模组放入中栏。已安装的依赖会随启用加入；缺失依赖会列出原因，不能用排序代替安装。
2. 检查依赖和顺序。自动排序保留合法关系；遇到循环依赖先处理冲突。停用被其他模组依赖的项目时，先确认连带停用范围。
3. 查看右侧详情的概览、权限、依赖、配置、文件和运行记录；需要更大阅读空间时展开详情。异常检查在顶部独立页面，不是保存前的步骤。
4. 关闭游戏后点击“保存”。管理器核对清单和声明 DLL 的内容指纹，建立恢复点，写入启用顺序与本次选择的原生批准；不自动执行异常扫描。游戏运行中或运行状态无法确认时，只能编辑草稿，不能写入。
5. 要直接游玩，点击“保存并启动”。它等待保存完成再启动，无需进游戏模组菜单补做批准；保存或启动失败时显示对应原因。用户主动隔离、未完成处置及实际写入冲突仍需先处理，未检查或高风险报告本身不阻断普通操作。

**启用时不弹权限提示。** “权限”页列出声明权限、已有检测证据及批准状态。保存写入的是用户对本次内容的启用批准，不是安全审计；未做检测时明确保持未知，不用声明权限冒充检测结果。包来源、清单或 DLL 改变后重新核对原生批准；手动检查报告另按全包内容判断是否过期。

当前游戏先加载 DLL，再应用保存顺序，因此中栏顺序和自动排序**不能保证 `Init`、Harmony 补丁或 Hook 的初始化先后**。

## 看懂四个独立状态

| 状态 | 表示什么 |
|---|---|
| 已安装 | 本地或工坊目录中发现了包 |
| 目标启用 | 当前草稿希望启用；保存后才写入游戏列表 |
| 原生批准 | 游戏可识别的当前内容批准；显式保存按用户启用意图写入，不代表做过安全检查 |
| 运行记录 | 最近一次 `Player.log` 提供的加载、失败或未加载证据；无证据时保持未知 |

“保存成功”确认本次选择和批准已写入，不代表模组兼容或运行成功。**“已启用”“已批准”都不等于本次正在运行。** 顶部进程状态说明游戏是否运行；详情和日志页的“本次启动对账”说明日志能证明哪些模组实际加载。

刷新会重新读取实际状态；如果游戏、Steam 或其他程序在草稿期间改了文件，保存会停止，先重新读取并核对差异，不用旧草稿覆盖新状态。

## 需要时手动检查模组

普通启用、保存和启动不自动扫描，不要求先建立检查报告，也不用清空旧数据。需要排查异常时点击顶部“模组检查”，进入独立页面；打开页面只读取检查记录，明确点击检查全部或选定模组后才扫描。页面显示进度、文件组成、覆盖范围、更新差异和异常证据，普通页面不请求检查接口。

基础检查读取全包内容并在隔离解析器中静态分析程序集，不执行候选 Mod，不需要 AI 或第三方上传。文件大、调用联网接口或系统 API 本身不是恶意结论。“未发现高风险项”只对应本次内容和规则，不能证明模组绝对安全。

未检查、过期、不完整或高风险报告只供复核，不自动停用、隔离或阻止保存和启动。更新后即使版本号没变，旧报告也不能当作新内容的结论；需要时主动重新检查。只有你已执行的隔离及未完成处置仍限制相关操作，解除或恢复须显式处理；不能阻止从 Steam 或 EXE 直接启动。

需要辅助解读时，可选择 AI 分析。它沿用设置中“日志分析”绑定的 Provider；先预览本次实际发送的有界报告摘要，再主动发送。AI 建议不会自动停用、隔离或修改文件，不使用 AI 也能完成本地检查和普通管理。

预览包括系统说明、报告摘要与固定问题，未配置 AI 也可在本地查看。摘要最多 24 KiB，包含状态、统计、部分发现及覆盖缺口，不含 DLL 原始字节、源码、完整文件清单、文件哈希或批准数据；截断会标明。报告或服务设置变化、请求失败或取消后，需要重新预览再发送。

需要杀毒引擎复核时，另行请求 Defender 检查；引擎结果与静态检查分别显示，不可用不会伪装成通过。Defender 云保护由系统设置决定。不要为了检查而关闭系统防护或添加白名单。

检查页中的停用和隔离会先预览依赖影响，再由你确认。本地隔离通过恢复点移出包；工坊隔离保留 Steam 文件和订阅，记录管理器内的隔离限制。恢复不自动启用或恢复原生批准；之后是否重新检查由你决定。

## 配置、方案与恢复点

- **配置：** 在详情“配置”页编辑游戏已有的键和值。没有运行时类型定义的键按原始字符串显示，不猜测开关或数值范围；未编辑键和未知字段保留。关闭游戏后保存，恢复点覆盖本次写入。
- **方案：** 保存一套原生 ID 与启用顺序，预览应用结果后送入模组草稿，再保存到游戏。方案不冻结 Steam 后续更新的文件。旧 MelonLoader 方案只能预览迁移，不能直接执行旧部署动作。
- **恢复点：** 从方案页“⋯”打开恢复点，核对对象后恢复。恢复也要关闭游戏并创建新的恢复点；恢复顺序不会复制或重放历史游戏批准。恢复点不等于存档备份。

## 检查工坊更新与阅读介绍

在模组页点击“检查更新”，查看工坊项的更新及下载状态；需要时点击“更新选中”或“全部更新”，工坊详情也可单独更新。仅关闭游戏后发起这些操作。Steam 接受下载请求后仍可能排队，只有后续状态确认完成才算更新成功；没有可靠进度时不显示百分比。更新不替你保存启用顺序，刷新也不会覆盖当前草稿。

“管理器自动更新模组”默认关闭；需要时再主动开启。这个开关只控制管理器是否主动请求更新，不会永久关闭 Steam 自己的更新，也不会撤销已接受的任务。连接慢、游戏运行和安装被占用是不同原因，按界面具体提示处理，不必反复退出已经关闭的游戏。

工坊列表可在卡片上直接操作，并选择每页 12、24 或 48 项。搜索、筛选和翻页先显示对应缓存或加载状态，再后台更新；目录信息过期不等于 Steam 账号断开。右侧详情优先显示包内封面，缺图或加载失败时补用对应 Steam 条目图片，可点开大图。公开信息和封面保留本地缓存，重开后可复用；缓存不是当前订阅或最新版本的证明。

工坊介绍可点击 AI 翻译，使用设置中为“翻译”指定的服务；原文始终可切回，也可取消。完整译文会缓存，原文 / 译文切换不发起新请求。只翻译已取得的片段，截断提示会保留；已有中文段落不重复发送给 AI。

## 在设置中管理 AI 服务

需要 AI 时，在设置页添加 Provider，填写服务地址、模型和密钥，再分别选择日志分析与工坊翻译使用哪个 Provider；两项可以使用同一个，也可以不同。已有单服务配置沿用，不需要为更新重新输入所有设置。

密钥可以仅本次使用或记住到 Windows 凭据；编辑时密钥留空会保留原密钥，改换服务地址则不会带走旧密钥。保存设置不发送分析或翻译内容，“测试连接”才会主动联系服务。正在使用的 Provider 需先改绑后才能删除；改绑不影响已开始的任务，只用于之后的新任务。

## 用日志判断运行结果

“日志”保留笔记本阅读区和右侧智能分析，主要游戏日志改为 `Player.log`。先看“本次启动对账”，再查错误上下文；日志时间早于本次启动或缺少证据时，不把旧日志当成本次成功。

不配置 AI 也能阅读日志。需要智能分析时配置自己的 OpenAI 兼容或本地服务，核对“发送给 AI 的内容”后主动发送。回复可以停止、继续或导出；分析建议不自动执行写入。不要发送密钥、完整存档或不需要的个人信息。
