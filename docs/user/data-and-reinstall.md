# 数据、备份与重装

## 分清应用、游戏和 Steam 管理的数据

在“设置 → 数据位置”查看当前路径。默认应用数据目录为 `%LOCALAPPDATA%\PSModManager`，首次启动和以后迁移均可选择其他本地磁盘。

| 位置 | 内容与处理方式 |
|---|---|
| 应用数据目录 | 数据库、缓存、日志、历史包库；工坊元数据、封面和完整译文缓存也在这里；原生方案、恢复点和导入暂存位于 `native-mods`。关闭程序后可整体复制备份 |
| 应用数据目录内 `mod-security` | 按安装保存检查报告、内容基线和处置记录。随应用数据备份；不要把隔离记录当作普通缓存删除 |
| 应用数据目录内 `mod-security-analysis` | 按内容和规则版本缓存静态解析结果，随应用数据迁移；旧缓存不能证明新内容已检查，也不是普通启动的前置条件 |
| 游戏根目录 `Mods` | 本地原生模组。停用只改变启用列表，不删除整个包 |
| Steam 库 `steamapps/workshop/content/4348910` | Steam 下载的工坊内容。管理器读取状态并通过官方接口请求订阅、取消或更新，不直接改包文件或 ACF |
| `%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen` | 游戏用户目录，包含 `SaveFile.es3`、`ModConfigs`、`ModData`、`Player.log` 和游戏存档等 |
| 旧游戏旁 `.psmm-*` 目录 | 旧版文件部署的暂存与恢复材料，不是新原生方案。保留到确认不再需要历史恢复时，不能直接当缓存删除 |

`SaveFile.es3` 不只包含模组状态。显式保存核对当前清单与声明 DLL 指纹后，写入启用顺序和用户启用批准，保留其他设置、类型字段和未知扩展，不搬动游戏存档。批准绑定当前来源、清单与声明 DLL，不代表已扫描；手动检查报告另外绑定全包资源。模组也可能把额外数据写入游戏 `UserData` 或其他自定义位置；只备份应用目录不能涵盖它们。

AI 密钥独立保存在 Windows 凭据，不写入分享方案。应用内迁移沿用凭据服务迁移已记住的记录；仅本次会话使用的密钥不变成永久保存。手动复制目录或换电脑不会自动复制系统凭据。Steam 登录在官方客户端完成，管理器通过官方接口使用已登录会话，不读取或复制其密码、登录令牌。

多个 AI Provider 的设置及分析 / 翻译绑定属于应用配置；各 Provider 的密钥仍按“仅本次 / 记住”分别处理，相同服务地址也不共用新 Provider 的密钥。旧单服务会成为默认服务，沿用原有凭据。完整译文位于应用目录的 `ai-translations.json`，工坊公开元数据和图片位于 `cache/workshop`；这些缓存不保存密码或密钥，也不是订阅、最新版本或游戏运行状态的证明。

## 把应用数据迁移到其他磁盘

1. 保存或放弃模组草稿，完成当前操作，并关闭其他版本的管理器。
2. 在“设置 → 数据位置 → 更换数据目录”选择新的独立空目录。目标不能与原目录互相包含，也不能位于游戏目录。
3. 核对范围后开始迁移。成功复制并校验后才切换启动位置；空间不足、文件占用或恢复记录异常时，保留原目录，不切换到不完整副本。
4. 重启并确认设置里的实际路径。新位置用于应用数据库、原生方案与恢复点、安全报告与处置记录、解析缓存和日志；游戏、工坊、存档仍在原位置。

原目录保留为备份。确认新位置可用后再清理大文件，保留 `.storage-redirect.json`，供已有启动方式转向新目录。默认启动位置另有 `%LOCALAPPDATA%\PSModManager-storage.json` 小记录。旧版遗留的 `nxm://` 注册不会因复制目录变成 Steam 集成；当前版本不使用该协议。

有待恢复操作时，先在原位置处理再迁移。旧游戏旁 `.psmm-*` 仍留在游戏同卷；新原生恢复点随应用数据搬动，不要将两种记录混用。

多个游戏安装可以保留各自历史记录。0.2.3 起，已验证属于其他安装的部署记录不再误阻断当前安装的工坊操作；当前安装未决记录或无法确认归属的记录仍会阻止相关操作。不要删除 journals 或 `.psmm-*` 来让按钮恢复可用。

## 恢复点与存档备份不是同一件事

每次原生写入前创建恢复点。恢复点用于相应启用顺序、配置或导入文件的恢复；它不是完整游戏或存档镜像。通过方案页“⋯”查看恢复点，核对对象后恢复；游戏运行中或无法确认进程状态时禁止恢复写入。

恢复状态只还原目标启用顺序并保留当前其他设置，不复用旧批准。恢复、换电脑或包更新后，重新核对实际内容并显式保存，才能为当前选定包建立批准。工坊包可能已经被 Steam 更新，恢复顺序也不会让这些文件回到旧版本。

手动检查中的本地隔离使用原生恢复点保存被移出的包；工坊隔离只记录逻辑阻断，不移动工坊文件或取消订阅。解除隔离不会自动启用，重新检查是可选操作。隔离不代表撤销模组已经执行过的副作用，也不是系统清毒。

备份重要进度时，先正常关闭游戏和管理器，再复制整个游戏用户目录，并根据所用模组说明备份 `UserData` 等额外数据。应用数据目录和原始模组目录 / ZIP 另存一份。不要只用旧数据库覆盖现有包库，也不要把程序能启动当作游戏已恢复。

## 重装或替换管理器

先保留旧窗口中未保存的选择，再正常关闭管理器。保留应用数据和游戏数据，完整解压新程序到另一目录，从新目录运行 `PSModManager.exe`，在标题栏或“应用信息”核对 **0.3.5**。旧窗口和指向旧目录的快捷方式不会自动升级；不要混用新旧 EXE 与 `_internal`。删除旧程序目录不会删除模组，也不会停用游戏里的模组。便携包不提供自动升级器。

使用新版时不用清空旧数据库。选择要启用的模组后可直接保存并启动，不会因旧报告过期、未完成或高风险而自动拦截；此前主动隔离或未完成的处置仍有效。保留检查与处置记录有助于比较更新差异和恢复，普通保存不把旧报告改写成新检查成功。需要读取检查记录或主动扫描时，进入顶部独立“模组检查”页面。

正式版不安装或修复 MelonLoader。旧加载器和旧版模组如仍留在游戏目录，先核对来源、备份并按各自说明处理；管理器不会自动删除用户已有文件。旧方案只提供迁移预览，未能映射的模组需找到正式版原生包后重新选择。
