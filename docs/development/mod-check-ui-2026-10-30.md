# 模组检查页界面重做（大量模组、报告分页、AI 聚焦证据）

2026-10-30。只改界面和 AI 预览的取材范围；检查规则、扫描器、处置与恢复、普通保存和启动的行为都没有变。打开检查页仍然只读取已有报告，只有用户点击才开始检查。

## 改了什么

| 位置 | 内容 |
| --- | --- |
| 顶部 | 按检查结果筛选：全部 / 需关注 / 内容已变化 / 未检查 / 未发现高风险，每项带数量。有未检查或内容已变化的模组时，右侧出现“检查未检查的 N 个”“重查已变化的 N 个” |
| 进度 | 改为一行：进度条、完成数、当前模组、阶段和文件 |
| 左栏 | 每个模组一行：名称、来源、版本、检查日期和状态；左侧色条标出风险。支持搜索（名称 / ID / 作者 / 工坊 ID）、排序（风险优先 / 名称 / 最近检查）、“只看已启用”。“检查选中 / 检查全部”放在列表底部。键盘：↑↓ 切换，空格勾选，Shift+↑↓ 连选，Ctrl+A 全选 |
| 报告 | 拆成页签：概要、风险证据、内容、变化、覆盖、AI 解读。概要页显示结论、四个指标（证据数、覆盖、体积、与上次相比）、最值得关注的 3 条证据、Defender 和处置操作 |
| 大报告 | 风险证据可按级别筛选和搜索；收起时显示第一处定位（文件 · 方法）；展开后先显示 5 处，可展开全部；IL 偏移显示为 `IL_xxxx`。证据、文件和变化列表每次显示 60 条，需要时再加载 |
| AI 解读 | 可以解读整份报告，也可以在某条证据上点“AI 解读这条”，只围绕这条证据提问（最多 12 处定位）。发送前仍然先本地生成完整消息预览，确认后才发送 |
| 联动 | 模组页详情的“⋯”菜单新增“在模组检查中查看”，跳到检查页并选中该模组（不会自动检查）；检查页标题下有“在模组页查看” |
| 模组页 | 没有可更新的工坊模组时，隐藏“更新选中 / 全部更新”按钮 |

## 后端改动

`security.ai.preview` 新增可选参数 `finding_ids`（1–16 个 finding ID）。

- 指定的证据排在最前面，每条最多保留 12 处定位；其他证据仍按严重级别排序，每条 3 处。
- 摘要超出大小上限时，先删其他证据；只剩指定的证据仍放不下时，拒绝生成预览，不会悄悄去掉。
- 报告中不存在的 ID 返回 `AI_SECURITY_REPORT_CHANGED`。
- 预览和发送绑定同一组 ID，`send` 仍会核对与预览完全一致。

不传 `finding_ids` 时，行为和以前相同。

## 反编译：尚未实现

现在 AI 拿到的是静态解析器给出的定位（文件、方法、IL 偏移、调用目标、规则说明），不是反编译后的源码。产品里的元数据解析器（`tools/PSModManager.Metadata`）只依赖 .NET 运行时，不带反编译库。

如果要让 AI 读反编译代码，建议按下面的约定扩展，界面不需要再大改：

1. 解析器只对报告中被命中的方法生成反编译片段，每个方法设字数上限，仍在无网络的 LPAC 进程中完成，不执行 DLL。
2. 报告的证据项增加 `snippet`（片段文本）和 `snippet_truncated`。
3. `project_report` 只在 `finding_ids` 指定的证据里带上 `snippet`，并在发送前预览中完整显示。
4. 需要单独评估：引入反编译库带来的许可和体积、解析耗时，以及片段在预览里的可读性。
