# 功能验证与旧用例索引

版本：2.0。验证围绕本次实际改动，不设全阶段审批。这里定义目标，不复制任务动态PASS；实际结果见台账和对应测试记录。

## 1. 核心操作检查

| 行为 | 简单判定 |
|---|---|
| 添加/安装 | DLL、目录、ZIP正常进入目标；点击一次普通安装按钮即可 |
| 启用/停用 | 实际文件位置及界面状态一致，停用文件不在加载器扫描范围 |
| 卸载/重装 | 删除所选Mod范围并更新列表，能重新安装 |
| 范围/解压 | 不越出支持的Mod目录，不执行安装脚本 |
| 常见失败 | 无效目录、坏ZIP、占用、权限/空间错误给准确结果和重试入口 |
| 可选功能 | 方案、日志、备份、配置、启动和AI只在相应功能使用时验证 |

当前直接动作及可选 AI 以各任务的实际消费者结果为准；不能用旧计划/批准UI测试宣布新流程已经实现。安装完成也不等于游戏玩法兼容通过。

## 3. 检查层级

单元/集成检查证明对应逻辑或文件行为；用户入口使用实际消费者检查。构建只说明产物可构建，不替代安装功能。缺少桌面、实机、联网或打包环境时明确未测，继续不依赖它的工作。

不要求每项功能进行全部强杀矩阵、磁盘满/断电演练、多档DPI、真实provider和玩法验证。选择足以证明当前改动的少量有效检查，遇到实际问题再扩大。

## 4. 历史阶段门

G0～G5退出当前执行前置条件。旧状态、原人工意见和旧用例结果仍保留作历史记录，不改成PASS，不从任务数量或文档存在推导通过。人工体验反馈按用户安排进行，不设审批会。
