# 0.3.2：模组检查独立于日常使用

## 本轮决定

用户明确要求“检查所有/选定 Mod 是否有异常”作为单独功能，普通功能不变。本版替代 0.3.0/0.3.1 的自动安全门禁：普通启用、保存和启动不扫描、不调用 AI、不等待检查结果。既有温室布局、三栏管理、工坊、方案、设置及日志功能保持。

| 操作 | 0.3.2 行为 |
| --- | --- |
| 启用、排序 | 只修改草稿，不弹权限框、不自动检查 |
| 保存 | 核对原生清单和声明 DLL 指纹，创建恢复点，写入顺序及用户启用批准，再回读确认 |
| 保存并启动 | 保存完成后直接请求启动，不插入安全检查或第二次确认 |
| 模组检查 | 单独打开面板，选择全部或列表选中项，明确点击开始；显示当前项、文件、阶段和完成数量 |
| 检查报告 | 显示组成、差异、证据和覆盖缺口；未检查、过时、不完整或高风险均不自动改动启用状态 |
| AI 解读 | 选择已有报告，预览实际消息和 Provider，明确确认后才发送；复用设置中的日志分析服务 |
| 停用、隔离、恢复 | 用户主动选择并确认；隔离/未完成处置仍受保护，恢复不自动重新启用或批准 |

普通操作仍遵守游戏运行状态、写入互斥、依赖和配置有效性、恢复点等原有保护。只有检查结果退出日常流程，不把这些实际写入保护一并取消。

## 为什么上一版保存很慢

对当前使用的数据目录只读核对发现，最近一次保存先逐个生成 9 份安全报告，报告写入从当地时间约 22:35:12 持续到 22:36:08，随后原生恢复记录最终为 committed。代码中 `prepare_enable` 将静态分析和游戏原生扫描串在保存之前，内容首次检查因此占据了约一分钟；不能仅凭界面等待把这次操作认定为死锁。

本版删除该自动入口。原生内部 revision 检查不再重复读取运行日志或构造完整展示快照；每次保存只在返回时读取一次运行证据。写入前仍即时复核内容，不能把优化做成跳过来源变化校验。

### 当前模组副本的保存耗时

使用当前已安装的 **9 个真实工坊包副本**，共 **60,542,537 字节**，其中声明 DLL **39,430,656 字节**，在独立游戏目录、存档和生产写入守卫下测量；原文件和真实存档未写入，也未执行 Mod。

| 测量 | 耗时 |
| --- | ---: |
| 第一次显式保存 | 3.499 秒 |
| 原选择再次保存 | 0.970 秒 |
| 同一批副本加约 7.34 MB 合成运行日志后的首次保存 | 3.808 秒 |

这是本机隔离测量，不是所有机器或任意包大小的性能保证。证据：`.preview/native-manual-approval-20261030/real-package-save.json`、`log-cost.json`。

## 批准表示用户选择，不表示安全认证

显式保存仍写游戏兼容的 `modTrust`，免去在游戏菜单重复同意。绑定内容为当前原生协议要求的 ID、来源、Workshop ID、清单及声明 DLL 顺序/内容。

没有做检查就不填检测结果：`detected=null`，附 `psmmApproval.source='manager'`、`basis='user_enable'`、`scanStatus='not_scanned'`。界面显示同意启用，并将检测权限标为尚未检查，不将清单声明冒充实际检测。

当前游戏原始 `ModTrust.Match` 成功后会跳过原生 `ModScanner.Scan`。因此本版没有声称“管理器先批准、游戏之后仍会替用户扫描”。用户需要异常检查时主动使用独立功能。游戏加载或 Mod 初始化仍可能失败，保存成功与实际运行证据保持分开。

## 手动检查与 AI 的实现

- 静态解析在现有 LPAC 元数据进程中进行，不执行候选 DLL。体积大、联网、反射或 P/Invoke 本身不等于恶意。
- 进度使用 `security.activity` 读取内存，不反复遍历包、重读报告。完整状态/详情仅在需要时读取；关闭面板后后台检查继续，普通草稿和保存可使用。
- `item.blocking` 只代表用户隔离或未完成处置；分析告警使用 `review_reasons`，高风险状态为 `high_risk`。
- 内容改变或中断保留旧报告，并明确旧/不完整状态。损坏单份报告不阻止普通操作，也不隐藏其他报告；手动重查生成新报告并保留坏文件，无法比较时明确没有有效基线。
- `security.ai.preview` 本地构造经过白名单、脱敏、有界的报告摘要和完整消息，不发网络请求。确认后的 `security.ai.send` 复核报告、Provider 与预览一致，重复确认不重复发送。
- AI 分支没有工具调用或处置能力。报告中的名称、字符串、描述均作为不可信材料，不把其中的指令当作用户请求。原始 DLL、完整反编译源码和任意文件不发送。
- Defender 保持用户显式选用；不可用不妨碍基础静态检查，其云行为由系统配置决定。

旧的合法报告、配置、缓存和恢复材料无需删除；旧报告的历史阻断字段不再参与普通操作策略。损坏的处置索引仍需明确修复，不能用清空记录的方式抹掉用户主动隔离。

真实 Steam 订阅、真实游戏/Mod 执行、真实付费 AI、Defender 实扫、本轮完整用户数据迁移及其他系统 DPI 未执行。进程测试只运行自编译的等待程序；AI 测试只请求自有 localhost；真实包只复制后在隔离目录分析原生保存协议。游戏菜单免重复操作由原生协议与隔离保存闭环支持，尚未以真实游戏游玩验证。本轮不提交、不推送、不发布。
