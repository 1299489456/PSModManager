# 工作台与用户流程

## 1. 当前方向与已有界面

2026-10-12 用户明确要求简化为本地 Mod 管理器。主要流程为“选择游戏 → 添加 Mod → 安装”，随后直接启用、停用和卸载。AI、方案、日志、简单备份和历史均为辅助功能，不能成为安装前置；不设置审核、阶段放行、证据批准或安装后运行验证手续。

PS-03-07 已将默认模组页接到 `mod.list/action`。方案页只在用户打开时挂载，普通流程不发送 profile/plan 请求或原生批准确认。PS-04-01 新增独立的可选 AI 页：打开才读取设置，点击测试或发送才联网，关闭取消 AI 请求。基础管理不依赖 AI 配置；可选方案/历史仍保留原接口及历史未测范围。

PS-04-03 在 AI 页显示已登记 Mod 的名称、版本、简短理由和一个安装/启用/停用按钮。用户点击后沿用普通管理的进度、取消、错误和文件状态刷新，主模组列表同步更新；不打开方案或批准页面。没有点击仅显示建议；成功卡片不重复执行。清除会话/更换游戏会丢弃旧卡片，过期建议给普通重新提问提示。AI 设置和基础管理继续独立，完成表示文件操作结果。

## 2. 布局与交互

继续沿用 RimCrow 紧凑多栏、列表与详情、主题、菜单和键盘习惯。固定参考提交为 `a7e875112a175a914bb4706a82589d96d62adc70`，原源码只读。复用组件必须接到 PSModManager 的显式桥接和新业务服务，不恢复 RimWorld、Workshop、SteamCMD、旧更新器或旧数据迁移入口。

顶部显示当前游戏位置、添加 Mod 和启动游戏。主工作区显示 Mod 列表与启用状态，右侧详情先展示名称、版本、文件和普通提示。默认页面不陈列计划、代次、HMAC、引用保护、运行待验证或恢复审批信息；必要的技术详情可放在日志或展开项中。

方案可用于保存、切换一组选择，日志用于排障，AI 作为独立可选面板。没有方案也能直接安装和管理 Mod；启动与会话验证也为可选功能，不阻挡核心管理接通。功能尚未实现时隐藏入口或明确提示，不展示假的成功反馈。

正文以 15px、次级信息 14px、Mod 名称 16–17px 为基准，保持清晰的字号、间距与信息层次。主题通过管理器私有 `config.json` 保存，保存失败保留旧值。哈希、共享归属等信息按需展开，不挤占主列表。

默认列表支持本页名称/版本搜索、分页、详情和原生键盘按钮操作。安装/启停/卸载修改实际 Mod 文件；失败显示原因并刷新状态，长动作可取消。导入后“去安装”刷新并定位新增版本，重开重新核对记录与文件。Ctrl/Shift 多选、拖动、撤销和重做属于可选方案编辑，仍只编辑方案；普通列表未新增这些批量功能。展示顺序不表示游戏加载顺序。

## 3. 主要流程

| 用户动作 | 普通服务行为 | 用户看到的结果 |
|---|---|---|
| 选择游戏 | 发现或选择安装，读取 Mod 列表 | 游戏位置、已安装 Mod 和无法识别项 |
| 添加 DLL、目录或 ZIP | 读取支持的文件并加入本地包库；必要时选择包内项目 | 名称、版本、添加结果；无安装脚本执行 |
| 点击安装 | 同一后端入口完成目标检查、文件复制和结果刷新 | “已安装”或具体错误；无需先建立方案或批准计划 |
| 启用 / 停用 | 普通服务安装或移出游戏扫描目录内对应 Mod 文件 | 实际启用状态；游戏运行中需要退出时直接提示 |
| 卸载 Mod | 删除或移走对应已管理 Mod 文件，刷新列表 | “已卸载”；不删除游戏根、存档或无关目录 |
| 清空 Mod 目录（未接入） | 后续按需提供所选范围的一次清理 | 当前普通列表只卸载选定 Mod，不提供目录清空 |
| 保存 / 切换方案（可选、原接口） | 保存选择只编辑方案；应用保留原计划/批准接口 | 已保存或已应用；普通 Mod 按钮不经过此页 |
| 查看日志 / 诊断（可选） | 读取选中日志和本地规则 | 相关错误、来源和可理解的建议 |
| 从备份恢复（可选、原历史接口） | 原回退入口仍有计划和确认，本卡未重写 | 结果以原接口及其历史验证范围为准 |
| 启动游戏（可选） | 启动所选游戏，避免重复启动 | 已启动或启动错误；不自动展开玩法验收流程 |
| 使用 AI（可选、纯文本已接入） | 问句/手选文本流式聊天；工具与建议动作以后按需接线 | 设置、目标、回复/错误、取消可见；未配置 AI 仍完成本地管理 |

导入继续支持 DLL、目录、ZIP；未增加其他压缩格式。导入到库与安装到游戏是两个清楚的动作，可在添加结果中提供“安装”按钮。只读扫描或从已有 Mods 复制到库时不移动原文件，真正的启停、卸载必须在普通管理入口中执行并反馈。

遇到同目标不同内容等明确冲突时，展示文件和处理选择或直接错误，不增加通用风险审核页。普通目录校验用于保证操作限于选定 Mod 范围；不因可选诊断的未知结论强制用户完成额外流程。

## 4. 方案与原有 UI 行为

2026-09-29 已完成的方案双列表、跨栏拖动、同栏排序、原子编辑、撤销/重做和重开持久化仍为当前实现。添加 Mod 使用独立包库弹窗，成功后关闭、清除搜索并定位新增行。Mod 详情是右侧独立栏。

接管当前按扫描、选文件和包名将已安装 Mod 复制入库；“全选本页”和选中计数帮助用户选择，不是批准平台。清单导入确认名称、版本和缺失项后创建方案，缺失项提供去包库添加入口。

主方案页的“检查方案”和整块兼容结果已按用户要求移除，后续不再加回。后台兼容关系可用于普通安装时的具体提示，不以新的计划检查面板替代已移除页面。

历史 UI 人工结果、自动检查与截图分别保留。旧 G1/G2 未通过的记录不改为通过；新开发不再把这些门或人工审核作为继续安装功能开发的前置条件。人工反馈用于修复实际可用性问题，不要求用户审核每次安装。

## 5. 状态、错误与取消

主列表使用“已安装”“已停用”“未安装”“安装中”“安装失败”等普通状态。名称、版本和文件来源不明确时照实显示。方案有未应用修改时显示“未应用”，保存方案不冒充已写入游戏。

安装成功表示实际文件操作完成，直接显示“安装完成”。未运行游戏不是安装失败，也无需在主列表反复显示“运行待验证”。日志若显示某次运行自停用或加载失败，可在诊断中说明，不自动改写安装结果。

进度能计数时显示实际计数，否则显示正在处理；错误提示包含具体失败原因与可行操作，例如关闭游戏、重新选择文件或重试。长操作可取消，并报告已经完成或未完成的结果。UI 重开能够恢复当前任务显示，不隐瞒后台仍在执行的操作。

意外中断优先由现有服务处理；处理不了时显示受影响的 Mod 和普通恢复、重新安装或卸载入口。现有代码中的恢复阻断尚未移除，后续简化须同步服务及测试，不以隐藏恢复页绕过真实未完成操作。目标产品不让用户管理 journal、引用保护或人工恢复审核。

## 6. 可用性检查

开发验证重点是添加、安装、启停、卸载、实际错误反馈和可选方案/AI入口。组件测试、构建、真实 WebView 操作和人工使用反馈各自说明覆盖范围；不以构建成功代替能操作，也不为简单 UI 修改新增审核层。

键盘、焦点、中文/长名称、小窗口、高 DPI 和状态非纯颜色提示按界面改动检查；未测项如实记录。大列表性能有明显问题时记录样本与耗时并修复，不以所有档位人工签字作为正常开发前置。历史基准和 DPI 结果保留，不扩写为当前版本已经全测通过。
