# 0.3.3：检查是独立页面，不是启动步骤

## 用户要的使用方式

日常路径保持“选择模组 → 保存 → 启动”。需要排查时，用户自己打开与“方案”并列的“模组检查”页面，选择全部或部分模组，查看报告及可选 AI 解读，再决定如何处理。

本轮替代 0.3.2 的弹出检查面板。普通模组页、方案、创意工坊、详情和启动按钮不创建检查工作区，不自动读取报告，也不在启动失败时跳转到安全详情。检查页面拥有自己的选择、进度、报告、AI 和处置记录。

## 普通操作与检查页面的边界

| 场景 | 行为 |
| --- | --- |
| 启动管理器、模组页、方案页、工坊页 | 不请求任何 `security.*` 接口 |
| 普通保存与启动 | 不请求检查报告，不启动扫描，不调用 AI，不等待检查完成 |
| 首次打开检查页 | 才创建检查工作区，读取已有报告；打开页面本身不开始扫描 |
| 选择检查项 | 在检查页自身多选、全选，不要求先去模组页选择 |
| 点击检查 | 才检查全部或选定项，展示实际进度与文件证据 |
| 离开检查页 | 未开始检查时停止读取；已主动启动的检查可后台继续，仅轮询轻量进度，完成后不在其他页面读报告 |
| AI 解读 | 本地预览实际消息，用户确认后才请求所选分析服务 |
| 处理模组 | 用户根据报告主动决定；报告不会自动停用、隔离或修改批准 |

游戏运行、并发写入及恢复保护仍属于普通文件写入的既有规则。用户之前主动设置的隔离或未完成处置继续被尊重；这只是读取处置索引，不执行异常检查或分析报告。

## 验收要求与证据

本轮新增 UI 验收必须从应用 bootstrap 开始计数，不能在点击保存前清空计数，从而遗漏自动请求。进入检查页之前，模组/方案及首次保存启动的 `security.*`、AI 请求都应为 0。进入检查页后，读取报告、手动选定/全部检查、AI 预览与确认发送分别验证；离页后的普通保存不等待后台检查。
