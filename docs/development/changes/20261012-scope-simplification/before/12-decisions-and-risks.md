# 决策与待验证事项

日期：2026-09-28。以下为开发基线选择，不表示功能已验证。变更时记录原因、受影响任务与重新验证范围。

## 决策记录

| ID | 决策 | 原因与影响 |
|---|---|---|
| ADR-001 | 固定 RimCrow 提交裁剪，源仓库只读 | 保留交互资产，阻止旧业务副作用；由 PS-00-01 出取舍清单 |
| ADR-002 | Python/pywebview/Vue 主线，独立 net10 元数据 helper | 减少 UI 重写；游戏 net6 不受影响；PS-01-02 负责隔离，不仅是进程拆分 |
| ADR-003 | M3 才允许部署，M1/M2 提供真实可用只读/组合编辑入口 | 每阶段有消费者；不等待 AI 才开始验证 |
| ADR-004 | 不可变库+普通复制；停用内容在游戏扫描树外 | 防止硬链接污染、扫描规则差异和未知二级加载 |
| ADR-005 | ActionPlan 为唯一计划名，事务提交和运行验证分开 | 统一两组原报告草案，杜绝“已复制=已修复” |
| ADR-006 | 浏览器 RPC 首版关闭，桌面显式 API 白名单 | 原浏览器桥接暴露过宽，且首版无远程控制需求 |
| ADR-007 | 首版只交付 Windows x64 便携包，选 PyInstaller | 降低安装器/多打包链维护量；不依赖管理员权限 |
| ADR-008 | 原生字段适配器逐项开放，不统一按 TOML 重写 CFG | 真实样本存在扩展语法和持久进度 |
| ADR-009 | 首版手动应用升级；自动更新列 M6 | 先证明数据迁移与回退，避免沿用 RimCrow 更新源 |

## 文档冲突处理

原 HTML 报告将同名程序集缺失日志列为候选原因；主 Markdown 补充了 MelonLoader v0.7.3 源码规则及集合核对。本方案采用后者，但规则限定版本和指纹。报告中的 OperationPlan/ActionPlan、不同事务示意和目录草图由 02–04 统一，不要求开发者任选一套。

未确定的“模组自动更新来源”“真实存档隔离”“游戏内观测 API”均有 M6 任务，不阻塞 M1–M3 的离线能力；不得为了填空捏造作者清单或 API。
