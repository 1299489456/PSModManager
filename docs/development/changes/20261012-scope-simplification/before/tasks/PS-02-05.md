## 实现步骤

1. 接通导入/接管预览、详情/版本选择、双列表、批选/分组、草稿撤销。2026-09-29 用户反馈后移除编辑页显式兼容检查操作及结果，后端检查保留供后续部署计划消费；变更不等于未来 planner 已验收。
2. 对未解析包/漂移/只读环境给出可操作错误，M2不开放游戏写入。
3. 清单导入导出由受控文件选择器提供，经profile.import_preview/import_commit校验source_handle和预览hash；源变化拒绝旧预览，复用一致任务反馈。
4. 使用真实WebView+自制安装完成导入→选版本/编辑→重开→导出→再导入闭环并汇总G2；兼容 API/计划阻断单独验证，不将已移除的检查页面记为当前产品消费者。

## 验收标准

1. 不是mock列表：数据经过真实库/SQLite/bridge并重启后可用。
2. 所有操作只写管理器数据根，合成游戏树保持完全不变。
3. 草稿变更、冲突、未知项和待应用状态明确；不显示部署成功。
4. 按 RimCrow 操作习惯，跨双列表拖入/拖出支持单项及 Ctrl/Shift 多选批量启用/停用；结果写入真实 Profile 草稿，支持撤销、重做和重开保持。拖动仅编辑配置，不直接部署游戏，也不将显示顺序解释为加载顺序。此项依据 2026-09-29 用户明确反馈，不能用只读列表内排序替代。
5. 后续人工反馈补充同栏排序与跨栏指定插入位置，启停和顺序作为一项编辑原子保存。普通行内按钮与复选框保留原生键盘行为；添加、接管与清单导入有可见状态和结果。用户已要求人工复核推迟到 M3/M4 完成后，自动检查不能将延期项改写为人工通过。
