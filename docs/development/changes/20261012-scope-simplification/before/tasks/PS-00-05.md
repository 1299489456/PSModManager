## 实现步骤

1. 创建自制最小DLL源、Melon属性替身/内容资源、日志/配置/安装树；不提交真实游戏DLL。
2. 实现 -Task/-Profile 路由及明确测试清单；synthetic默认临时数据/配置/TEMP且拒绝真实游戏根。
3. 采集命令、版本、exit、case计数、跳过、哈希和产物，按08写summary。
4. 将00-01~04验证也纳入可重复入口；禁止0测试、缺依赖或跳过必要case被计PASS；不自动恢复依赖。

## 验收标准

1. 任意未知任务/profile/缺测试入口明确非零；必要未执行项保持NOT_RUN/BLOCKED。
2. fixture可再生且注明来源；所有写入落在创建并校验过的测试根。
3. runner自身的失败、超时和子进程清理能被检验；文档校验与产品结果独立。

## 验证内容与命令

- tests/unit/test_verification_runner.py：退出码、0用例、超时、授权配置缺失、profile隔离。
- 运行PS-00-05 synthetic并归档真实输出；汇总G0但不虚构未完成桌面检查。

需要的 Profile：synthetic。命令在项目根目录执行；所列产品文件/测试/harness为本任务或前置任务交付物，当前规划阶段尚不可运行。缺工具、依赖或必要资源时记录BLOCKED/NOT_RUN，不自动安装、不用空测试替代。

runner由PS-00-05实现，必须精确映射本卡测试和必要CASE；不支持的Profile不得返回成功。
