# 开发路线、依赖与阶段门

共37项：33项主线、4项延后增强。M0–M3共24项构成离线管理MVP；M4增加AI，M5形成可交付便携版。每个任务的输入、目标文件、步骤、验收和命令见独立卡片；状态唯一来源是 [台账](task-register.json)。

## 工时口径

工时为规划区间，包含实现、必要接线和针对性验证；不包含等待用户/环境、未知逆向研究和发布审批。它不是完成日期或承诺，也不能由文件数量线性估计。主线总计740–1108工程小时；应先完成M0后按实际复用量修订估算，并保留变更原因。人工实机时间与环境等待单独记录。

## 阶段门

G0：独立桌面/数据根、严格桥接和真实harness可用。G1：真实只读基线与诊断工作台。G2：包库/Profile/导入真实消费者。G3：事务恢复、配置、启动、限定真实游戏闭环。G4：执行时授权与真实provider最小闭环。G5：固定产物干净机器、迁移/恢复及交付文档。

各门从NOT_RUN开始，必需任务和用例见 [验收矩阵](07-validation-matrix.md)。每个门要求其前序门PASS；证据失效需重新检查受影响门。MVP在G3通过时成立，不必等待AI/在线源/companion；完整主线发行候选需G5。实际硬件断电耐久性作为扩展实验，未实测必须在产品限制中明确。

## 范围变化

增加需求时先补需求ID、责任卡、依赖和验收；任务拆分保留原ID与替代关系，不复用旧ID指代新功能。没有前置的页面库或占位类不算阶段交付。实施中不因本卡困难自动开始下一卡。
