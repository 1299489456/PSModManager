### PS-03-04 部署历史与恢复页

工作台“部署历史”绑定当前真实安装，通过 `deployment.history` 后台任务读取真实事务、当前代次、回退来源和未完成记录。显示“运行待验证”，保留策略说明所有来源受引用保护，不提供强制恢复或清理按钮。历史记录的“回退这次部署”只申请预览；后端重新核验文件和备份后，用户沿用计划差异、原生批准和执行入口。回退生成新代次，当前编辑方案不随回退修改。

外部漂移显示相对目标、记录预期、当前观察和是否成功保全。失败不会显示已恢复；“复查已手动恢复的文件”只调用实际复查，再重读历史与部署状态。未修复、坏副本或坏备份保持阻断。真实 WebView 自动输入、组件测试和人工视觉/DPI 验收分别记录，人工审核仍按用户安排在 M3/M4 后统一进行。

## 2. 主要流程

| 用户动作 | 后端行为 | 反馈与退出条件 |
|---|---|---|
| 首次选择安装 | discover/select→只读扫描→指纹/库存/日志关联 | 展示未托管项；游戏目录零修改 |
| 搜索/分组/批选 | 本地 UI 与管理器用户元数据 | 中文/空格/百分号文件名保持原样 |
| 查看某模组 | 展示文件名、程序集、显示名、版本、roles、证据 | 显示元数据来源与未知项 |
| 导入 DLL/ZIP | import_preview→用户选择范围→import_commit | 写私有库，不自动部署游戏 |
| 勾选/跨列表拖动当前配置 | 通过 profile.edit 修改 draft revision，检查关系 | “待应用”；跨列表拖动整体启停，显示顺序不决定加载顺序 |
| 查看差异 | plan.create/inspect | 新增/替换/移除/保留/冲突，备份和重启需求 |
| 批准并应用 | plan.approve→deployment.apply | 显示明确阶段；游戏运行中拒绝写入 |
| 启动 | 检查恢复状态/进程→固定安装启动→绑定会话 | 启动与玩法验证分别显示 |
| 回滚历史 | 新恢复计划→差异批准→rollback | 外部修改时保全并要求解决冲突 |
| AI 诊断 | 选证据范围→会话→提案卡片 | 无证据标未知；卡片提交普通计划流程 |

## 3. 状态文案

2026-09-29 人工反馈修复将“模组”设为默认主工作区，直接显示真实 Profile 对应的启用/停用双列表，用户界面称为“方案”。方案用于保存一组 Mod 的版本和启停选择。新建、复制、清单导入导出归入“管理方案”；“添加 Mod”用独立弹窗显示本地包库，成功后关闭弹窗、清除搜索并定位新增项。启用/停用两栏支持 Ctrl 多选、Shift 同栏区间选择、实际拖放、逐项按钮和右键菜单；一次拖动原子保存启停和显示位置，撤销/重做整体生效，重开保留。同栏上下移动和跨栏插入都有可见落点，移动集合保留原相对顺序。采用应用内指针捕获，移动超过阈值才开始拖动；Esc、取消、失去捕获、方案或修订变化均中止。外部拖放数据和列表外松开不作为配置指令。搜索只过滤显示，不改库或加载顺序；插入锚点来自当前可见行。

“文件与归属”读取锁定发布版本的真实文件清单和库校验结果。同目标同内容、同目标异内容的其他包版本分别列出；其他 owner 是索引归属声明，不等于其库字节也已验证，更不等于已部署。顶部“接管”先要求完整扫描，再预览并逐文件确认，只复制批准的不可变文件到管理器包库；漂移或失败需重新扫描/预览，不自动重试确认。

“游戏文件”页独立展示 M1 的扫描文件、预计加载和日志；主标签采用“预计加载”，主界面移除“只读库存”等开发阶段提示。M2 仍只编辑管理器中的方案，应用到游戏与游戏启动属于 M3，未交付功能不显示成可用按钮。相对参考的布局、完整键盘习惯及高 DPI 视觉差异仍须单列验收，不能仅用桥接和拖拽测试宣称视觉一致。

2026-09-29 第二次人工反馈后，按用户要求从方案编辑页移除“检查方案”和整块兼容结果。后端兼容图、来源解释和计划阻断规则保留，后续 M3 planner 消费同一契约；不把未来 AI 作为当前依赖/写入校验的替代。旧检查页面的人工/桌面证据仅属历史，当前 API 检查与未来部署页面验收分别记录。“游戏文件”的日志分析入口保留。

接管预览显式执行“扫描并读取清单”，扫描失败显示具体原因和受影响文件。完整扫描后由用户点击文件复选框或“全选本页”，界面展示选中数、包名必填和确认按钮不可用的原因；未选文件不入库。导入/接管成功刷新包库，导入结果提供“去包库添加”入口。清单读取完成打开独立确认弹窗，显示名称、版本数和缺失项；明确确认后才创建方案。

方案编辑页正文以 15px、次级信息 14px、Mod 名称 16–17px 为基准，主次由字号、字重、间距和结构共同区分。Mod 文件详情使用独立右侧栏，先显示名称、版本、可用状态和文件条目，再按需展开共享版本、归属说明与哈希。主题使用管理器私有 `config.json` 持久化，保存失败保留旧主题并显示错误，不依赖桌面 WebView 的临时网页存储。

用户明确将新 UI 的人工复核统一推迟到 M3/M4 完成后。本轮自动检查与窗口截图不替代该人工结论，也不自动放行 G1/G2。历史三档系统 DPI 的用户通过保留，但不能扩写为所有后续 UI 版本均已通过。

每行分别显示“配置：已选/未选”“部署：匹配/待应用/漂移/未托管”“运行：未知/已注册/自停用/被遮蔽/委托/失败”。可简化视觉密度，但详情必须保留三层。

“撤销编辑”仅还原草稿；“回滚部署”创建磁盘恢复计划。主按钮不能统称“保存”。事务 committed 后显示“部署完成，运行待验证”；部分检查通过显示“启动验证部分完成”，不会自动变成“问题已修复”。

阻断：未完成事务、缺失确认硬依赖、路径/所有权冲突、基线过期、运行中写入。潜在 Harmony 风险和信息提示默认不阻断；未知兼容清晰提示，由具体规则决定是否允许计划。

## 4. 失败、取消与恢复

进度显示可知计数与阶段；未知总量显示不定进度，不虚构百分比。长任务可取消；applying 取消文案说明将安全恢复。UI 重开通过 task/session 快照续接；事件乱序/重复按 task_id 和 sequence 去重。

启动发现 recovery_required 时先展示恢复页，普通部署/管理器启动游戏禁用；仍可浏览库存、查看证据和导出脱敏诊断。恢复失败保留具体文件、原因和安全退出说明。

## 5. 可用性与性能目标

在记录硬件/磁盘/样本规模的 Windows 基准上测量：5000 个合成组件的搜索筛选 p95≤200ms；正常本地按钮操作反馈≤100ms；扫描不在 UI 线程解析文件；取消后5秒内停止新扫描任务，子进程最迟按工具时限清理。初次全量哈希时间单独记录，不用固定总扫描秒数掩盖磁盘差异。

基准不满足时记录测量和瓶颈，不能调小样本后宣称通过。键盘导航、焦点恢复、快捷键冲突、125%/150%/200% DPI、中文/长路径、屏幕尺寸至少1280×720验证；状态不能只靠颜色。实体路径与实现名不出现在普通用户主流程，只有详情/诊断按需显示。

前端纯 store 测试、构建、真实 WebView 桥接和人工桌面流程分别出证据，不能互相替代。
