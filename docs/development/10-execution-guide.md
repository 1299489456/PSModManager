# 开发执行约定

2026-10-12 调整为简单本地 Mod 管理器：直接安装、启用、停用、卸载是核心；启动、配置编辑、恢复历史和 AI 可选。PS-03-07 已接通直接动作，结果以本卡当前消费者验证为准，不继承旧批准流程的通过记录。

不使用 task-doc-generator、task-runner、task-completion-handoff 及该系列技能。任务卡限定范围；一次只做用户指定项，不自动开始下一项。

## 1. 每次执行的顺序

1. 读适用 AGENTS、README、台账、任务卡，以及本次确实会改到的契约。
2. 核对当前文件与现有修改，保留用户工作。只检查要复用的前置模块是否实际可用；不要求其历史状态 VERIFIED 或 G0–G5 PASS 后才开发。
3. 确定最小改动与能证明用户动作的测试。已有实现先复用，必要接线在本卡完成；不重建整套审核、批准、历史恢复或测试基础设施。
4. 实现实际入口，运行相关测试并读取结果。安装动作必须产生实际文件变化，单次构建或 Mock 页面不能证明安装可用。
5. 修复本次影响的失败，保留旧失败记录。没有实际运行的检查仍为 NOT_RUN/BLOCKED，不因为范围调整改成通过。
6. 更新必要说明和台账引用，简短报告行为、文件、测试和缺口，完成后停止。

人工体验反馈用于处理具体问题，不是放行条件。2026-09-29 的延期安排与旧失败保留；G1/G2 的历史 BLOCKED 不阻止不依赖这些人工结论的本地开发。

## 2. 状态和历史

`task-register.json` 记录任务进度与实际测试结果。TODO 尚未做；IN_PROGRESS 正在做；IMPLEMENTED 已接通但有必要测试未完成；VERIFIED/PASS 只表示声明范围已有实际通过结果；BLOCKED 写清具体外部障碍；DEFERRED 为暂不做。

旧 G0–G5 状态只作历史索引，不是任务门禁。取消门禁不改写旧 PASS/FAIL/BLOCKED/NOT_RUN，也不把原先缺失的实机、DPI 或人工结果补成通过。

FR/NFR/CASE ID 保留用于追溯。旧恢复、审批、多代对账等 CASE 属已有实现回归或可选能力，不要求全部重跑才交付首版直接管理。跨任务 CASE 只记录本次实际测试的部分。

## 3. 测试和依赖

优先直接使用现有 `.venv` Python、pytest、Node 内置测试及桌面 harness。任务卡给出的 runner 命令仅在 `verification-profiles.json` 已映射该任务/profile 时使用；未映射则用本卡实际创建的直接入口，不能承诺尚不存在的 runner。

产品源文件或测试还没有时，在负责该功能的任务内创建最小入口。缺依赖不自动安装；`uv run --no-sync`、`dotnet build --no-restore` 等只使用已经具备的环境，前端 prebuild 也不隐式恢复依赖。

测试应覆盖具体用户行为、目录不越界、ZIP 安全解包、普通占用/空间/权限错误及可选备份。不要为每个小改动默认启动全仓、多代恢复、逐持久边界强杀、物理断电或多档系统 DPI 检查。发现相关回归再扩大测试范围。

## 4. 文件和共享接口

保留现有修改；不在原 RimCrow 目录改造。不因模块曾从 RimCrow 导入而重新导入或运行其旧入口。共享 DTO/API 变化只同步受到影响的文档和消费者。

子任务确有价值时明确文件所有权；不同时修改同一共享文件。任务 ID 保留用于追溯，标题和目标按当前范围调整，不隐藏代码与新目标之间的差异。

## 5. 资源边界

开发默认合成安装和隔离 data root。已有且适用的授权持续有效，不重复询问。真实 RimCrow 源目录只读；未获授权不写入或启动真实游戏、不碰正式存档，不安装依赖、提交、推送或发布。

文档修改不会扩大资源授权。实机或联网不具备条件时，完成独立本地工作并说明没有测试的范围。真实游戏启动、存档或外部 AI 只有在本次动作确实需要且获得对应授权时使用，不为首版增加额外审批流程。

## 6. 文档和结束报告

新旧目标不同就调整文档，不把已发生结果改成新目标的通过证据。历史 evidence 保留原文；任务卡、依赖和台账反映当前安排。

验证记录只需能重现本次检查：命令、退出码、用例计数、关键结果和未验证范围，复杂封存材料不再默认必需。文档结构检查与产品测试分开记录。

结束报告简明说明实际行为、改动文件、相关测试与剩余缺口。无需例行汇总阶段门、生成新人工审核表或要求用户批准进入下一阶段。下一项仅作提示，不自动执行。
