# 按改动验证

版本：2.0。测试用来确认功能，不设阶段审批或统一大验收包。

## 1. 选最小有效检查

| 改动 | 应运行 |
|---|---|
| 文档/配置 | JSON、引用、任务依赖与文字一致性检查 |
| 安装/启停/卸载 | 合成安装的真实文件变化与状态；正常路径和相关错误 |
| 普通按钮/页面接线 | 实际消费者；必要时真实WebView点击，不用Mock代替已声明的桌面行为 |
| 备份、配置、日志或启动 | 只测本次涉及的可选功能 |
| AI | 本地界面/工具和真实provider分开；没联网明确未测 |
| 便携交付 | 实际产物启动和依赖说明；没有打包环境就记录缺口 |

构建通过不等于安装能用，未运行不写PASS。已有检查通过后不无理由重跑；发现相关回归再补测试。

## 2. 当前工具怎么用

已有 `scripts/verify.ps1 -Task <ID> -Profile <profile>` 仍可回归原实现；以 `verification-profiles.json` 中真实映射为准。旧路线包含复杂审批/journal/多代恢复检查，不再是新首版的全部必验要求，也不把旧PASS用于新的一次点击流程。

任务未映射runner时，在对应任务内用现有pytest、Node或桌面harness建立最小直接检查，写清实际命令。没有依赖不自动安装；没有对应入口不运行空测试凑通过。

## 3. 不再默认要求

逐持久边界强杀、多进程锁/PID竞态、系统级沙箱证明、物理磁盘满/断电、多档系统DPI、45/43全真实Mod清单及完整玩法闭环，均不作为所有安装功能的门。已有这类结果与失败保留，实际修该问题时再选用。

普通UI确实需要交互桌面时，锁屏会使可信输入检查无法执行；只说明该分项未完成，不操控锁屏、不把它扩成后续所有任务的审批障碍。开发机测试、真实游戏和发行环境结果各自说明，不互相替代。

## 4. 记录够用的信息

记录改动版本或文件、命令、退出码、通过/失败/跳过数、关键结果和未测范围。简单变更不要求每轮生成完整输入/产物封存、审计页和人工审核表。

`evidence/` 保留旧运行记录；新测试可以放在对应任务的独立目录，保存相关输出即可。旧PASS/FAIL/BLOCKED不删除、不回填。日期、截图、Mock和构建结果不能替代没有执行过的消费者测试。

## 5. 状态

TODO未做；IN_PROGRESS正在做；IMPLEMENTED实现完成但必要检查有缺口；VERIFIED/PASS只用于当前声明范围实际通过；BLOCKED写明具体条件；DEFERRED按需再做。

历史任务记录对应当时的范围，当前简化目标不是自动重验结论。G0～G5已退为历史索引，人工体验按用户安排进行，无统一阶段放行。可选回退历史、配置或AI的未测结果不阻挡独立核心管理接线。

## 6. 资源

默认合成安装/隔离数据根；不安装缺依赖。原 RimCrow只读。真实游戏启动/写入、正式存档、联网AI与发布沿用已有授权边界，适用授权不重复询问。

无需为验证直接安装而规划存档/Steam Cloud隔离或系统运行时修改；这些是另选功能或资源，不属于普通管理验收。

## 7. 文档检查

`pwsh -NoProfile -File docs/development/tools/Validate-DevelopmentDocs.ps1` 检查现行说明、卡片、JSON索引和引用，不执行产品测试，不递归扫描旧测试fixture与历史快照。历史证据引用仍检查文件可定位，但其内容不因此自动有效或通过。

旧极端 `Environment.FailFast` 系统弹窗、符号链接权限等记录保留在原evidence；本次文档调整没有修复这些代码/环境问题。
