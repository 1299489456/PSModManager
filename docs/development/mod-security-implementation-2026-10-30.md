# 0.3.0 本地模组防护实施与验收

## 要交付的闭环

在现有温室风格模组页完成 **检查内容 → 展示差异 → 识别高风险 → 阻止受控启动 → 可恢复处置**。启用操作不新增权限弹窗，游戏批准仍由游戏完成。本轮不接 AI，不上传样本。

## 已完成的实现

1. 元数据解析：扩展现有无网络能力 AppContainer 工作进程，以独立协议解析 IL 调用、PInvoke、敏感字符串与嵌入资源；保持导入预检协议兼容。
2. 安全服务：绑定安装、有效来源、全包内容和规则版本，持久保存报告、版本差异与处置记录。调用既有原生恢复事务，不建立第二个游戏文件写入器。
3. 宿主集成：封闭 ID/token API、受控启动核对、关闭排空与数据迁移保护。
4. 界面：三栏、底篮和草稿交互不变；新增行状态、安全详情、选中/全部检查、处置预览及恢复入口。
5. 交付：同步 0.3.0 版本与用户说明；通过隔离 API、真实解析隔离、界面关键路径和冻结包检查后提供本地包。

入口位于模组页工具栏和详情中的安全检查区域。先检查选中或全部模组，再查看容量构成、文件差异和风险证据；需要处置时，先预览受影响的依赖，再停用或隔离。处置记录提供恢复入口。

| 操作 | 实际行为 |
| --- | --- |
| 检查内容 | 在无网络能力 LPAC 工作进程中读取托管程序集元数据和 IL，不加载执行候选 Mod；报告列出文件、代码、元数据、资源和重复内容 |
| 展示差异 | 与该来源上次报告比较新增、删除、修改及容量变化；首次检查明确没有历史基线；报告与解析结果缓存到私有数据目录 |
| 识别高风险 | 同一方法的敏感凭据路径、框架文件读取与网络发送指令组合触发高风险，保留文件、方法、指令位置和程序集引用身份；体积大或单独联网不直接判毒 |
| 阻止受控启动 | 启动前重新读取期望启用包的全部路径和内容；未检查、过期、覆盖不完整、高风险、隔离或损坏记录均阻断，并能定位模组 |
| 停用与隔离 | 展示依赖闭包并创建原生恢复点；本地包移出到恢复区，工坊包只停用并持久逻辑隔离，不删除 Steam 文件或退订 |
| 恢复 | 本地包按原内容恢复、工坊包解除逻辑隔离；两者均不自动启用或批准，恢复后需要重新检查 |

安全服务接口与持久化语义见源码仓库的 `backend/mod_security/CONTRACT.md`。宿主入口为 `backend/app/security_api.py`，前端主要入口为 `NativeSecurity.vue` 和 `securityRuntime.js`。文件写入继续复用 `NativeModService`，没有新增另一套游戏文件写入器。

## 验收条件

| 环节 | 必须验证的结果 |
| --- | --- |
| 内容检查 | 全包路径及内容纳入指纹；静态解析不加载执行候选程序集；大量嵌入资源能统计完整总量，展示截断与分析未完成分开 |
| 差异 | 新增、删除、修改及容量变化可见；首次检查没有虚构历史基线；更新后旧报告不能授权当前内容 |
| 风险 | 大小、网络、反射、PInvoke 不单独定罪；高风险结论有具体规则、文件与指令证据；失败/超限不能显示通过 |
| 启动 | 对期望启用包重新核对真实内容；未检查、过期、不完整、高风险及隔离阻止管理器启动；停用包不阻断无关运行 |
| 处置 | 展示受影响依赖；写前恢复点；运行中拒绝；工坊包仅逻辑隔离；本地包可移出并恢复；恢复不自动启用或批准 |
| 生命周期 | 重启保留记录；损坏记录明确报错；扫描时迁移被拒绝；关闭等待已接纳工作，不遗留后台写 |
| 用户体验 | 扫描不锁住浏览和未保存草稿；可定位阻断模组；报告使用普通用户可理解的结论和下一步 |

## 使用边界

- 保护范围为管理器的受控启动；Steam 或 EXE 的外部启动不受此门禁控制。
- 检查只证明当前规则和覆盖范围内的结果。已经运行的恶意行为不能通过停用撤销。
- Defender 只按用户显式操作执行不修复扫描；不可用单独展示。其系统云策略仍由 Windows 管理。
- 所有会修改包或游戏状态的验证使用隔离目录；真实游戏目录仅作只读分析，不启动真实游戏、不改变订阅。

### 独立审查发现并修复的缺口

- **有效来源不确定**：游戏可能跳过缺少 `IMod\0` 标记的本地包，再加载工坊副本。现在检查声明 DLL 的完整内容；无法确认来源或同来源候选重复时报告不完整，不猜 Steam 遍历顺序。
- **敏感路径遗漏**：加入 `loginusers.vdf` 等凭据特征，并用真实隔离解析器验证。
- **同名类型误报**：高风险组合要求框架 AssemblyRef 名称、公钥 token 和作用域匹配；本地或未签名外部程序集伪造 `System.IO.File` 等名称不再冒充框架调用。
- **恢复被自己的中断记录拦住**：只允许精确关联同一安全处置操作的待恢复事务；其他未完成操作继续阻止写入。
- **损坏 DLL 无法原样恢复**：安全恢复校验原备份和发布前暂存包的完整内容身份，允许还原原本损坏或包含未声明 PE 的包，但保持停用、撤销批准并要求重新检查。
- **新增门禁影响旧入口**：只有明确识别为纯 IL2CPP、没有 Mono 标记且该安装没有原生/安全历史时，保留旧的直接游戏启动行为；混合、未知和有历史的安装仍接受门禁。

早期一次闭环样本缺少必需的 `Capabilities` 清单元素；修正样本后通过。WebView2 第二轮曾因长驻旧宿主配合新版 schema 解析器失败；以新宿主完成第三轮验证，没有加入协议降级。扩展旧测试时另有 5 项调用已移除的 `inventory.inspect` / `inventory.scan`，在到达解析器前返回 `UNSUPPORTED_COMMAND`；它们不计入本轮通过结果，也未恢复废弃入口。

## 本地交付与验证边界

本轮本地包输出到 `.preview/mod-security-portable-20261030-01`。冻结后的实际解析器、完整 API 闭环、旧版数据隔离升级和窗口启动结果写入该目录；全部通过后才更新仓库的 `docs/development/current-local-delivery.json`。此文档随包冻结，打包后的结果以交付指针及其证据为准。

- 源码和 WebView2 的有写入验证使用自制惰性样本与隔离数据目录；未执行真实 Mod、未启动真实游戏、未变更 Steam 订阅。
- Microsoft Defender 实际扫描未运行；已验证签名/位置约束、固定参数及返回结果分类。用户可显式调用，系统云策略可能联网。
- 未验证非 96 DPI 的系统缩放。AI 风险分析和第三方样本上传不在本轮范围内。
- 管理器门禁只控制经管理器发起的启动；外部启动和已发生的恶意行为需要用户另行处理。
