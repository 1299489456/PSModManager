## 实现步骤

1. 在现有包库/Mod 列表接入安装、启用、停用、卸载动作；选择或导入后可以直接安装。
2. 增加最小后端业务入口，解析选定安装和包版本，复用现有文件执行能力；内部需要计划时自动封装，手动操作不出现二次审批步骤。
3. 启用把 Mod 放进加载器允许目录；停用将该 Mod 的代码/资源移出扫描范围，保留包库以便再次启用；卸载只移除该 Mod 安装文件。未知文件和用户配置不顺带删除。
4. 给出进度、完成与普通错误提示，基本目录校验和 ZIP 越界防护保留。可选备份是简单操作，不要求历史代次或恢复审核。
5. 使用真实后端和合成安装验证 UI 动作及重开结果；需要且已有启动接口时接入按钮，真实游戏验证按已有授权另记，不阻止本地管理交付。

## 验收标准

1. CASE-037：从实际 UI 导入/选择 Mod → 安装 → 停用 → 启用 → 卸载，目标文件变化、库记录和显示结果一致，重开后仍正确。
2. 普通手动动作点击一次即可执行；不以前置 Profile/计划批准/恢复历史操作为条件。构建或 Mock 不代替这些文件操作结果。
3. 路径越界、ZIP 越界和普通占用/空间/权限错误得到明确反馈，错误不能显示完成；仅删除本 Mod 文件。
4. CASE-038 真实游戏、日志和玩法记录为可选实机补充；没有授权或实机环境时说明未验证，不要求 G3 或人工审核放行。
