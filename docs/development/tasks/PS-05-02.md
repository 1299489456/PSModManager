## 实现步骤

1. 选定PyInstaller构建路径，包含前端dist、规则/资源、helper及其运行时策略，记录锁文件/工具版本。
2. 使用独立产品名称和数据根；禁用原更新渠道及用户数据迁移；便携程序数据默认LocalAppData。
3. helper优先独立自包含产物，实际可复现和体积由本任务证明；WebView2缺失明确提示，不静默安装。
4. 产物排除真实游戏/DLL/存档/key/开发数据库，生成hash与依赖材料清单。

## 验收标准

1. 便携产物包含 Python 和 helper 运行时，列明 Windows、.NET Framework、WebView2 等前置，并验证实际冻结入口启动。与 CASE-046 当前责任及 PS-05-03 对齐：干净机器在具备环境时另测，本机隐藏开发 PATH 不记作干净机器通过。
2. 源码包/发布包不含真实资源和秘密，程序文件与用户数据分开。
3. 构建重复有可解释差异；不能仅一条build成功即宣称可交付。

## 验证内容与命令

- tests/integration/test_package_layout.py：清单、资源/helper、禁止文件、命名空间。
- release profile执行构建与产物检查；依赖恢复/下载必须事先具备授权。

适用 Profile：synthetic、release。仅运行本次需要且已有入口的路线；真实资源和联网路线按现有授权选择，不是独立本地开发的必经步骤。缺工具或入口如实记录，不自动安装。

直接测试入口（文件尚未存在时由本卡创建最小测试后运行；游戏/桌面路线不要仅凭文件名自动启动）：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/integration/test_package_layout.py -q
```

已有 runner 映射时可选：

```powershell
pwsh -NoProfile -File scripts/verify.ps1 -Task PS-05-02 -Profile synthetic
pwsh -NoProfile -File scripts/verify.ps1 -Task PS-05-02 -Profile release
```

上述 runner 命令只在当前配置已映射本任务/profile 时使用。未映射则使用本卡实际测试的直接入口；没有运行的检查不记通过。
