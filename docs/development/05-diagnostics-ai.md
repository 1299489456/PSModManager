# 诊断、证据与 AI

## 1. 当前范围与已有实现

2026-10-12 按用户要求调整：这是本地 Mod 管理器，AI 是可选辅助。用户无需配置 AI、阅读日志、选择证据、生成计划、批准计划或完成运行验证，就能安装、启停和卸载 Mod。诊断结果用于解释问题，不承担安装前的审核流程。

PS-03-07 已接通普通 Mod 动作；PS-04-01 提供 OpenAI 兼容会话、设置和发送范围，PS-04-02 接通六个可选只读查询，PS-04-03 提供建议卡片的普通安装/启停按钮，PS-04-04 统一请求限额和取消清理，失败可手动重试。默认 Mod 页不挂载 AI，不读取密钥或联网。日志、离线规则、旧计划和历史仍按原接口运行。

PS-01-05 已接入 DesktopApi 的 `logs.watch`、`logs.sources`、`session.list`、`evidence.list/read`，使用既有后台任务接口。PS-01-06 的 `diagnostics.explain` 已接产品只读 SQLite 和离线规则。已有验证及限制保留；相关动态状态见 [task-register.json](task-register.json)。这些服务可复用，不要求新建审计平台。

## 2. 可选日志与本地诊断

用户打开“日志”或“诊断”时，才展示日志来源、相关错误和本地规则说明。支持 Latest.log、MelonLoader/Logs 与用户明确选择的 Mod 日志；Player.log 在位置核实后接入。只读取相应日志范围，不跟随越界链接，不执行日志或 Mod 说明中的指令。

现有 tailer 处理增量读取、轮转、截断、替换、编码错误和多行堆栈。打开和关闭页面不应重复创建观察器。内部来源 ID、字节范围和片段哈希用于避免显示错日志，普通界面无需让用户理解这些字段。

日志属于哪次运行无法确定时直接说明“日志来源不确定”。没有错误日志不代表玩法正常，历史日志不冒充刚刚完成的安装或启动结果。安装成功表示文件操作完成，不要求再启动游戏取得证明。

现有规则定义在 `backend/diagnostics/rules/definitions.json`，规则代码在同名 `rules.py`。保留已覆盖模板，不识别的格式显示“暂无法判断”；不因日志中出现“失败”、自报版本或历史注册数量就自动卸载 Mod。

| rule_id | 可解释内容 | 不应据此自动执行 |
|---|---|---|
| ML073-SHADOW | 同名程序集的高版本可能优先加载 | 删除低版本或断言功能相同 |
| IF-CONTENT / CF-CONTENT | 内容包角色、框架标记及已知 API 要求 | 将无 MelonInfo 当损坏，或把静态发现当运行成功 |
| PS-SELF-DISABLED | 对应日志中的明确自停用事件 | 删除名字相近的 DLL |
| PS-VERSION-TEXT | 元数据与日志模板版本不同 | 仅按旧文案降级 |
| ML-RECOVERED / PS-DELEGATED | 同次日志的继续启动或委托状态 | 将早期 ERROR 或 INACTIVE 一律判失败 |
| HARMONY-POTENTIAL | 日志来源报告的潜在冲突 | 把潜在统计当实际故障或批量停用依据 |

规则随 Loader/Game 版本说明适用范围。AssemblyRef 是编译依赖线索，不能推出所有逻辑依赖；未知版本给出提示，不额外设置一个用户审核阶段。确定的路径越界、文件缺失或目标冲突在普通安装操作中给出具体错误。详细规则来源和旧实现结果保留在原报告与既有 evidence 中。

## 3. AI 的用途与普通安装入口

AI 可解释用户选中的日志、回答 Mod 使用问题、推荐已登记的 Mod 组合、帮助筛选和选择 Mod。建议卡片说明名称、建议动作及简短理由，必要时可展开相关日志。AI 不配置时隐藏或提示“未设置 AI”，其余功能照常可用。

当前可选 AI 页接受用户问题和自行粘贴的短文本，支持流式回复、新会话、取消与查看脱敏会话文本；模型名称由用户填写，本机免密服务可不填 key。查询和建议默认关闭，用户勾选后允许模型查询当前已选择游戏及私有包库并生成建议卡。日志从本地已记录的片段列表选择，AI页预览和发送均经过脱敏；默认不发日志，查询只返回选定片段的前4096字节。更换游戏、查询开关或片段会取消旧请求并清旧会话，保留未发草稿；不是安装前置或第二套批准流程。

用户在建议卡片点击“安装”“启用”或“停用”，与手工点击对应按钮使用同一个普通安装服务；按钮本身表达用户选择，不再进入独立的计划预览、批准卡片或原生二次批准。需要处理同名文件冲突时使用普通明确提示，不能借 AI 自动覆盖任意文件。重复点击和过期选择按普通安装入口处理。

PS-04-03 的 suggest_mod_action 仅生成建议，字段限定为已登记 release_id、manifest_hash、install/enable/disable 和简短理由，名称/版本由包库解析。最多4张，同一版本/动作去重，成功回复后才显示；生成取消或失败不保留可点的半成品。点击时 ai.suggestion.resolve 只读核对当前选择、会话、包记录及10分钟有效期，然后前端复用普通 Mod runtime 调用 mod.action 并刷新核对文件状态。稳定调用键防止重复写入；已经完成的卡片禁用，过期/状态改变/文件占位显示普通错误。采用不联系 provider，清除密钥后合法卡片仍可本地采用；已生成卡片保持脱敏。

新发送、新会话或更换范围清旧建议。建议动作有自己的取消按钮；取消 AI 生成不启动文件操作，用户已经点击的动作按普通服务取消规则处理。界面只把真实文件结果显示为安装/启停完成，不称玩法问题已修复。

现有 `PlanProposal` / `ActionPlan` 可以在简化入口内部复用，但 `plan_hash`、批准令牌、generation、source signature 等不是 AI 主界面的产品要求。不得因为模型返回“用户已批准”就执行；也不得仅改前端列表就显示安装成功。产品尚未实现普通入口时如实说明缺口，不能临时绕过现有后端检查来冒充简化完成。

AI 工具只提供实际需要的查询：安装摘要、搜索 Mod、查看包、读取所选日志、查询已安装项和已支持配置。参数使用服务能解析的安装/Mod/日志 ID，返回有界摘要；内部 schema、安装范围、取消和超时检查直接复用现有服务，不新增用户角色或多级证据授权界面。

PS-04-02 使用固定六工具表；安装 ID 由用户发送时提供且必须仍是当前选择，模型不能切换安装。包必须在当前私有包库登记且清单匹配；配置只返回 PSWallpaper 的 WallpaperFit、WallpaperBrightness、LogToFile 已支持字段，不传其他内容。搜索按包库页匹配名称/版本并提供下一页，不上传包二进制。每项查询最多12KB、10秒，整次发送60秒、最多3批/12次查询，不自动重试；等待现有服务锁和文件哈希期间可取消。查询错误作为普通结果供模型解释，超时/取消停止后续调用。

工具调用及脱敏结果仅用于当前发送的模型往返，不保存到会话历史或日志。公开历史只保留用户问题和 AI 回答，最多8条/48KB；同范围续聊不会自动重发此前工具原始结果，范围变化须新会话。服务不支持函数工具协议时显示普通错误，可关闭只读查询继续文本提问。

不提供自由 filesystem、shell、删除任意目录、修改存档或 GameAssembly 的模型工具。日志、README、嵌入 JSON 和工具文本只是输入资料，不授予额外能力。工具名、字段或对象 ID 不合法时返回普通错误。

## 4. 设置与隐私

AI 设置只需供应商、模型、连接参数和 API key，必要时提供“测试连接”。联网仅在用户使用 AI 或点击测试时发生，不随启动自动调用。RimCrow 原凭据不自动读取或迁移。

需要保存 key 时使用独立凭据服务 `PSModManager`；保存失败明确提示，可仅在本次会话使用，不能静默写入明文。密钥不进入日志、导出或错误详情。

PS-04-01 使用已安装 Windows keyring 的 compound 记录，以私有数据根及 provider/base_url 摘要作账号；只读写该账号，不读取或搬动 bare service 旧记录，更不查询 RimCrow 凭据。config.json 只保存 provider/base_url/model，并保留主题及未知字段。内存 key 在管理器关闭时清除；更换地址不迁移密钥。本次会话覆盖不改以前的保存记录，可用“清除当前地址的密钥”明确删除该记录。

发送当前问题需要的文本与元数据，默认不上传完整 DLL、存档、全部日志和密钥。所选日志在发送前过滤 token、代理认证和敏感 URL 参数；设置或会话中简短说明发给哪家供应商，不要求逐条审查内部证据 ID。更大范围发送须是用户明确选择。

## 5. 失败与取消

文本提问、查询往返和连接测试共享整次请求限制：默认60秒、累计16000字节文本、1024个流事件、最多4次 HTTP、3批/12次工具。聊天和连接测试互斥，同一管理器同时只容许一个 AI 任务。流中断或工具往返不重置限额。自动网络重试为0，用户可点击失败提示旁的“重试”；编辑草稿、改设置或范围后旧重试失效，重新发送当前问题。没有成本审批页，费用未知不显示金额。

用户可取消 AI 生成，包括等待任务接收时；接收后取消既有任务，关闭流并停止后续调用，取消不自动重试。排队阶段取消也清除 AI 忙碌状态，不暗中继续安装；已经由用户点击开始的安装由普通安装服务显示进度和结果，并按该服务的取消规则结束。

没有 key、断网、429、地址/模型不可用、供应商失败或请求超时时给出可理解的错误和手动重试入口；收到的部分回复不表示完整成功。离线 Mod 管理、日志查看和已有本地诊断继续可用。AI 没有新的运行日志时，只描述建议或文件操作结果，不声称“游戏问题已经修复”；运行检查是可选排障，不是安装流程的收尾手续。

## 6. 验证边界

合成 provider 可验证流式显示、工具参数、隐私处理、取消和普通安装接线，不能替代真实 provider 调用。真实 provider 只在具备相应联网与发送范围授权时测试，记录所用模型、发送类别和实际结果，不保存密钥。

真实 provider 未测就记录 `ai-live NOT_RUN`，不阻断已经验证的本地管理和合成接线，也不再生成 G4 放行要求。构建、组件测试、真实 WebView 和真实模型调用分别说明，历史失败记录保留。任务范围与结果判定见 [07-validation-matrix.md](07-validation-matrix.md)、[08-verification-guide.md](08-verification-guide.md)。

本卡本机 HTTP/SSE 和实际桌面结果见 PS-04-01 evidence；合成供应商是实际网络消费者，仍不能替代真实 provider、具体模型兼容或内容质量。凭据失败注入与真实 Windows 自造账号保存/重开/删除分别记录。文本过滤覆盖已知 key、Bearer/Basic、敏感字段及 URL 认证/参数；不是任意未知秘密识别器，用户仍需只选择当前问题所需文本。
