日期：2026-10-16。`prototype.html` 是第一版单文件可点击原型：双击即可在浏览器中打开，不需要构建，也不连接后端，里面的数据都是合成样本。标题栏右侧的“原型演示”下拉框可以切换各种情况（正式界面没有这个控件）。也可以用地址 `#demo=dirty&page=logs&dialog=import` 直接打开某个状态。

## 风格备选（2026-10-16 第二版）

先打开 `index.html` 并排比较。`prototype.html` 是第一版的浅色基础布局。三个风格版不再只是换颜色：每款都有自己的布局、交互方式和动效，只共用同一套样本数据和业务逻辑（开关先进入草稿、保存才写入游戏、导入不执行 DLL、AI 建议走同一个草稿流程）。

| 文件 | 风格 | 布局 | 标志性交互与动效 |
|---|---|---|---|
| `prototype-glass.html` | 玻璃拟态 · 夜航（深色） | 没有侧栏。底部是浮动玻璃 Dock，启动键是 Dock 里的香槟金圆钮；顶部是“灵动岛”胶囊；列表与详情是两块浮在夜景上的玻璃 | 灵动岛按状态变形：平时显示游戏和 MelonLoader，点开后展开为环境面板；有更改时变成保存条，保存中显示进度环，游戏运行中显示计时，通知也从这里出现。选中高光在行间弹性滑动，行内有跟随鼠标的高光，Dock 悬停时会放大。页面切换带景深模糊，背景光斑随鼠标轻微移动 |
| `prototype-cyber.html` | 赛博动漫 · 驾驶舱（深色） | 顶部指令栏（数字键 1–4 切页）+ 左侧状态仪表（加载器链路、启用数格条、警报、队列、“出击”按钮）+ 数据表格 + 目标锁定面板 + 底部系统终端 | 选中行时锁定框收缩吸附到这一行，名称以解码动画显示。更改进入“任务队列”终端，执行时逐行打印文件操作，并用块状进度条显示。卸载需要长按 1.2 秒，通知以终端打字的方式输出。启动时有开机自检（可跳过），页面切换用故障闪切。NAVI 副官的回复逐段出现，按 A/B 可以执行它给出的选项 |
| `prototype-solarpunk.html` | 太阳朋克 · 温室（浅色） | 顶部圆角“树冠”导航，带藤蔓下划线和太阳启动钮；Mod 以卡片网格分组，有更改时右侧出现“待保存篮子” | 启用时卡片上会长出嫩芽，停用时卡片褪色。每次开关都有一片叶子飞进篮子，篮子随之弹一下。卡片点开后在原位展开，其他卡片用 FLIP 平滑重排。卸载直接在卡片里确认，确认后卡片枯萎退场。日志页是横线笔记本，错误行像用荧光笔标记过；方案页做成种子包；首次启动时有太阳升起 |

玻璃拟态和赛博动漫按风格包规范使用深色底，这是用户确认过的做法。每个文件都是独立的单文件原型，双击即可打开；标题栏的“原型演示”下拉框可以切换状态。地址参数 `#demo=…&page=…&dialog=import|preview|env&ask=1` 用于直接打开某个状态，赛博版可加 `noboot=1` 跳过开机自检。

已用 Edge 无头模式驱动三款原型走过完整流程，没有脚本报错。流程包括：真实鼠标点击开关、Ctrl+Z 撤销、保存、日志页 AI 提问、导入、方案、设置，以及首次启动、未装 MelonLoader、游戏运行中、未配置 AI、空列表这几种状态。这些检查还没有覆盖：真实 WebView2 窗口中的性能（尤其是玻璃版的 `backdrop-filter` 和太阳朋克版的 FLIP 动画），以及“减少动态效果”系统设置下的表现（代码已经检测这一设置，但没有实际测试）。

## 第一版改了什么（三款风格版沿用这些信息架构决定）

| 现状问题 | 原型做法 |
|---|---|
| 顶栏同时放安装、导入、配置、方案、主题、应用信息等按钮，主次不清 | 改为左侧导航：游戏卡片、模组、日志与 AI、方案、设置；页面右上角只保留一个主按钮“导入 Mod” |
| “全部 Mod”和“加载列表”两栏穿梭拖拽，同一个 Mod 出现两次，而拖动顺序本身并不决定加载顺序 | 改为单一列表，每行一个启用开关；按“依赖库与插件 / Mod”分组，并提供“全部 / 已启用 / 未启用 / 需处理”筛选 |
| 详情栏在左侧，挤占主列表 | 详情移到右侧，显示启用开关、加载问题、位置、来源和文件；PSWallpaper 的“配置”入口从顶栏移到该 Mod 的详情中 |
| 保存和启动按钮放在底部状态栏，很难看出当前有哪些未保存更改 | 有未保存更改时，底部浮出更改条，列出“启用 X、停用 Y”，并提供撤销、保存、保存并启动；侧栏的启动按钮会随之变为“保存并启动游戏” |
| MelonLoader 面板一直占用一行 | 正常时只在侧栏显示一行状态；未安装时，模组页出现警告横幅，并提供一键安装 |
| 日志页按钮多、术语多（如“原文阅读 / AI 发送资料”“不附日志，普通提问”） | 改为日志来源标签、搜索、“只看错误和警告”；本地检查结果置顶并可一键定位；附件以可移除的标签显示，输入框下方说明这次会发送什么 |
| AI 的结论和 Mod 列表互不相连 | AI 回复可以引用到日志的具体行；建议卡片（如“停用”“查看”）执行后会进入同一个待保存流程；Mod 详情中也有“查看日志 / 让 AI 分析”入口 |
| 默认使用深色，并支持多主题 | 只保留一套浅色样式，设置页不提供主题选项 |
| 首次启动时没有引导 | 未选择游戏时显示三步引导：选择游戏 → 确认 MelonLoader → 启用 Mod |

## 交互约定

- 开关、导入后启用、应用方案、AI 建议都只修改草稿；只有点击“保存”才会写入游戏目录。这与现有 `mod.workspace.save` 的草稿模型一致。
- 卸载会立即执行，需要二次确认；有未保存更改或游戏正在运行时不能卸载。
- 游戏运行中时禁止保存，并说明原因。
- 支持把文件直接拖进窗口导入。导入前先显示文件去向的预览，并说明不会执行 DLL。
- 快捷键：Ctrl+S 保存，Ctrl+F 搜索，Ctrl+Z 撤销上一次开关，↑/↓ 切换选中项，空格切换启用状态。

## 落地时需要确认的点

1. 去掉拖动排序：现有文档说明显示顺序不影响 MelonLoader 的加载顺序。如果仍要保留排序（例如为以后的加载顺序功能预留），可以在“已启用”筛选下加一个拖动手柄。
2. “需处理”和行内“加载失败”标记需要把 `diagnostics` 的规则结果关联到具体 Mod，目前后端只在日志页使用这些结果。
3. 拖入窗口导入依赖 pywebview 的文件拖放能力，需要确认能否拿到本地路径。
4. 导入预览里的“安装位置”摘要需要汇总 `package.import_preview` 返回的每个文件的目标位置。
5. 选定风格后，只把该风格的令牌放进 `:root`，用来替换现有的 `builtinThemes.json`、`ThemePicker` 和主题设置。
6. 玻璃拟态大量使用 `backdrop-filter`，WebView2 支持该属性，但大列表滚动时的性能需要在真实窗口中验证。
