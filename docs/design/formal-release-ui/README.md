# PSModManager 正式版界面原型

2026-10-29 第二版。依据 [正式版升级方案](../../ProbablyStolen_FormalRelease_Upgrade_Plan_2026-10-28.md)（主要是 §4、§8）和游戏自带 Modding 界面的截图制作。`prototype.html` 是单文件可点击原型，双击用浏览器打开，不需要构建，也不连接后端。**用户已确认此版为界面和交互基线；正式实现保留它的温室样式与布局，不另行设计。** 实现和验收记录见 [0.2.0 正式版原生管理实现](../../development/formal-release-implementation-2026-10-28.md)。

## 第二版改了什么

第一版换成了一套新的“仪表盘”外观，和现在的温室界面差别太大，设置页等本来不需要动的地方也被改了。第二版的原则是：**现有的界面能用就原样保留，只在正式版确实需要的地方改动。** 配色、圆角、阴影和动效直接取自 `frontend/src/app/garden.css`。

| 部分 | 处理 |
|---|---|
| 标题栏、顶部导航、游戏安装牌子、太阳启动按钮、背景叶片 | 原样保留。导航里的 “Nexus” 换成 “创意工坊”，位置不变；“MelonLoader” 状态胶囊去掉，只在游戏运行时显示“游戏运行中 · 只读” |
| 页面标题、提示条、搜索框、筛选标签、叶片开关、底部弹出面板 | 原样保留 |
| 设置页 | 原样保留：概览 / 更新记录 / 许可与致谢，以及“数据位置”“本地检查”“关于”三张卡片 |
| 日志页 | 保留笔记本样式的日志和右侧“智能分析”。来源改为 `Player.log`，日志上方加了一行“本次启动对账” |
| 方案页 | 保留左侧方案列表和右侧“已启用 / 已停用”两栏。已启用一栏加上顺序编号；旧版 MelonLoader 方案只提供迁移预览；“⋯”菜单里加了“恢复点” |
| 创意工坊页 | 照搬现在 Nexus 页的结构：说明卡片、筛选与搜索、卡片网格，点开后在页内显示详情（“返回列表”） |
| 选择游戏安装 | 保留原来的面板，加了一段“识别结果”：三套版本号、运行方式、工坊和用户数据目录、旧版残留检查 |
| **模组页** | 按方案 §8 改为三栏：可用模组 → 启用与顺序 → 模组详情。外观沿用方案页的两栏（浅绿底色、白色圆角行、圆形多选框、叶片开关）。原来的“待保存”篮子保留，改放在页面底部 |

## 模组页

- **可用模组**：分为“已安装 · 未启用”“下载中”“需处理”（旧格式包、缺依赖、缺失依赖的占位行）；可筛选全部 / 工坊 / 本地 / 需处理；排序只影响这一栏。
- **启用与顺序**：带序号。有“自动排序”和置顶、上移、下移、置底按钮。底部注明这是“保存顺序”，点“为什么”可看说明。
- **模组详情**：封面、标签、名称、四格信息（版本 / 适用游戏 / 大小 / 更新），以及一条“生长路线”：已安装 → 已启用 → 游戏批准 → 运行。下面有启用开关和配置、文件夹、工坊页、更多按钮，以及六个页签：概览、权限、依赖、配置、文件、运行记录。封面右上角的按钮可以放大，在底部弹出面板里两栏显示全部内容。
- **待保存篮子**（页面底部）：没有改动时显示“与游戏中保存的一致”和待重启数量；有改动时变成黄色，列出变更，以及阻断问题、待游戏批准、待重启的数量（点击可跳到对应模组），右侧是撤销、重做、放弃、保存、保存并启动。每次开关，都有一片叶子飞进篮子，篮子随之弹一下，和现在一样。
- **交互**：
  - 启用 / 停用：拨动叶片开关、在两栏之间拖动、双击，或按 Enter / Delete / 空格。
  - 多选：点行左侧的圆圈，或按住 Ctrl / Shift 点选。
  - 调整顺序：Alt+↑↓ 移动，Alt+Home/End 置顶 / 置底。
  - 撤销 / 重做：Ctrl+Z / Ctrl+Y，或点提示行里的“撤销”。
  - 启用时，需要的依赖会一起加入；停用被依赖的模组时，会先列出受影响的模组，再确认。
  - 有阻断问题时不能保存；游戏运行时只能编辑，不能保存。

## 需求 1：启用时不再弹权限提示

1. 启用只是加入草稿，**不弹任何窗口**。
2. 列表行上只有一个小盾牌和权限数量（橙色是高权限，蓝色是中等权限），鼠标悬停时显示权限名称。
3. 权限都集中在详情里：概览页有“权限与信任”摘要，“权限”页签有完整内容。
4. 篮子里汇总“N 个待游戏批准”，点击后跳到该模组的权限页。
5. “保存并启动”的确认面板会把启动后需要游戏批准的模组**一次列出**，每项都可以点进权限详情。

批准仍由游戏完成：PSMM 不代为批准、不导入别人的批准记录，也不开启开发者模式（方案 §4.2）。

## 需求 2：详情比游戏自带的更详细

游戏自带的详情（截图 3）只有：封面、名称、作者、模组版本、适用游戏版本、一行权限文字、批准日期、启用按钮、设置图标和 Steam 图标。原型保留了这些内容，并补充了下面这些：

| 内容 | 游戏自带 |
|---|---|
| 标签：分类、版本、来源（工坊 / 本地） | — |
| 评分、订阅数，以及版本 / 适用游戏（是否匹配）/ 大小 / 更新日期四格 | 只有版本文字 |
| 生长路线：已安装 → 已启用 → 游戏批准 → 运行，每一步都说明当前状态，例如“已批准，重启后加载” | 只有“已于…获得批准” |
| 权限页：风险级别；每项权限的图标、中文名、代码名、说明，以及“已声明 · 已扫描”标记；清单声明、当前版本扫描、本机批准、最近一次启动四格；更新新增的权限会高亮；说明“这些权限不是系统沙箱” | 一行文字 |
| 概览：阻断问题与一键修复、更新提示、简介、作者提醒、基本信息（原生 ID、工坊 ID 可复制，DLL 与入口数量）、数据位置 | — |
| 依赖页：依赖关系图、需要 / 被依赖列表、与已启用模组的补丁交集（标“需运行验证”）、排序规则入口 | — |
| 配置页：`ModConfigs/<ID>.json` 键值编辑，标“类型未知”，保留未知字段，保存前备份 | 设置图标 |
| 文件页：包结构树、包检查、多入口说明、同一 ID 的两个来源（正在使用 / 被遮蔽）及切换 | — |
| 运行记录：最近一次启动的日志行、事件时间线 | — |

## 打开方式

- 标题栏的“原型演示”下拉框可以切换三种情况：10-28 本机快照、游戏运行中、首次使用（空库）。正式界面没有这个控件。
- 地址参数可以组合使用：

| 参数 | 作用 |
|---|---|
| `demo=normal\|running\|fresh` | 演示情况 |
| `page=profiles\|workshop\|logs\|settings` | 打开某个页面 |
| `mod=<原生 ID>&tab=overview\|perm\|deps\|config\|files\|log` | 选中模组并打开某个页签 |
| `enable=a,b` | 预先把模组加入草稿 |
| `dialog=save\|sort\|import\|install\|expand` | 打开某个面板 |
| `ws=<ID>`、`pf=<ID>` | 打开某个工坊条目或方案 |
| `still=1` | 关闭动画（截图用） |
| `selftest=1` | 运行内置自检 |

例如：`prototype.html#enable=furniture_plus,holiday_decor&dialog=save` 会显示有阻断问题时的保存面板。

## 样本数据

- 前 7 个模组的工坊 ID、版本、声明的权限、启用顺序，以及“只有物品详情在运行、其余 6 个已批准待重启”，来自 10-28 本机快照（方案 §2.2、§6）。
- 这 7 个模组的作者（“Custom Mod”除外）、简介、大小、配置值，以及除 `item_details` 以外的原生 ID，都是示意数据。
- PS 通用库、更多家具、节日装饰、价格面板、夜市天气、CheatMenu、`seasonal_core`，以及创意工坊页的另外 4 个条目，都是合成样本，用来演示依赖、缺失、同一 ID 有两个来源、下载中、更新新增权限、旧格式包等情况。它们的详情里标有“示例”。
- 封面使用和现在 Nexus 页相同的浅色渐变加嫩芽占位图；正式实现时换成工坊封面和包内的 `preview.png`。

## 已验证与未覆盖

- 用 Edge 无头模式，以现有截图的窗口大小 1366×860 截取了模组页、权限页、草稿与阻断、保存确认、自动排序、游戏安装、放大详情、游戏运行中、首次使用、创意工坊列表与详情、方案、日志、设置，另外截取了 1600×900 和 1100×760（窄窗口时详情改为右侧抽屉）。截图在 `.preview/formal-release-ui-shots/v2/`，不纳入仓库。
- 无头 Edge 不会播放 CSS 动画，底部弹出面板会停在屏幕外，所以截图时加了 `still=1`。面板确实已经打开（检查过页面结构），动画本身和现在应用里的一样。
- `#selftest=1` 共 124 项全部通过：
  - 渲染：13 个模组 × 6 个页签、13 个放大视图、缺失依赖占位。
  - 草稿操作：启用时带入依赖、篮子显示变更、拒绝旧格式包、缺失依赖造成阻断且不能保存、停用时提示反向依赖、一起停用、撤销 / 重做、置顶 / 置底、拖动改序、顺序警告、自动排序（修正顺序，且不改变无约束模组的先后）、筛选时不丢失隐藏项、叶片开关的启用和停用。
  - 页面与状态：各页面、工坊详情、旧方案、游戏安装面板、三种演示状态、保存后基线更新。
- **未覆盖**：真实鼠标拖动（只测了函数）、实际按键的快捷键、WebView2 窗口、系统 DPI 缩放、飞叶和面板动画的实际观感。

## 已确定的实现口径

1. 保留三栏比例、底部待保存篮子和列表权限小盾牌；窄窗口沿用详情抽屉，不重新设计设置页或日志页。
2. 演示数据换成实时读取的清单、配置和日志。当前结果可以与 10-28 原型快照不同，不能为匹配原型伪造状态。
3. “没有声明额外权限”不等于“无需批准”；批准状态独立读取，只能由游戏改变。
4. 自定义排序规则接入真实持久化、环检测及方案保存，不保留空入口。
5. 当前没有完整 IL 扫描或补丁交集证据的字段显示“未扫描/待核对”，不沿用示例中的扫描成功结果。工坊订阅交给 Steam 官方界面，匿名通道未验证时不启用。
